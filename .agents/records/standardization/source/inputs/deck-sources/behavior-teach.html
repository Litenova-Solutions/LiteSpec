Where Behavior sits

Behavior Turns Promises into a Specification Code Can Follow

Agents write Behavior from Intent; developers review it before code carries it. The Specify rule says what Behavior adds, and what it must leave to a person.

Specify adds

  • States and transitions of each aggregate
  • Invariants and other rules, each with its refusal
  • Refusals with stable codes, in precedence order
  • Consistency of every use case
  • Data classes with their erasure positions
  • Freshness of every query output
  • Access with tenant scope

Specify leaves open, as a draft question

  • a price, fee, rate or term
  • a market or payer
  • a personal-data retention period
  • a freshness a person can observe
  • any default or figure that varies by tenant, market or date

A receipt threshold of EUR 25 goes to the ballot with a recommendation instead of entering the setting silently.

The domain model

Aggregate: One Thing Kept Consistent, Changed Through Its Root

Each aggregate declares one kind, lists its states, and keeps a Transitions table and a Data table. Its rules and events are entries on its page.

entity

Default. States, transitions, data.

process

Multi-step: steps, exits, a driver.

store

State no invariant guards, with a named owner.

The domain model

Rules: What Holds, in Eight Kinds

A rule states what holds with its kind and statement, names what it constrains in governs, the refusal its breach produces in refusal, and the requirements it carries in fulfills.

KindMeaningDesign pattern
invariantHolds after every changechecked on every change
preconditionGuards behavior before it runsa guard the behavior passes
calculationDerives a value, proven by an examples tablea pure computation
cross-aggregateSpans aggregates; lives on a rule pagestored constraint or reaction
atomicityNames one atomic write groupone atomic write group
reservationHolds a claim until releasedBy releases ita held claim with its release
commercial-dataFreezes a value: frozenWhen, historyLinka frozen value with history
defaultStates a model defaulta default the model holds

Keep the negation in the name

rule/expense.approver-is-not-submitter. A rule name keeps the negation its statement makes. Check: rule-name-negation.

One calculation, many readers

A query and a command showing and recording one value both cite the same calculation rule in computedBy. Code carries a mark naming the rule, never the reverse. Check: calculation-without-table.

Reservations end

Every reservation names the use case that releases it, or never with its cost. Check: reservation-without-release.

Model invariant or setting?

A commercial, legal or tenant-varying default fulfills a requirement as a setting. A model invariant is a rule.

Use cases

Effects: Every Edge Declared, with One Verb and Its Timing

An effect is an edge from a use case, reaction or job to something else. Each entry carries exactly one verb. The effect graph across the project stays free of cycles.

issues

Runs another use case. Inline issues state sharesTransaction.

sends

A notification. On a command: after-commit or async only.

publishes

An outbound integration event.

calls

An external system operation. On a command: after-commit or async only.

effect-undeclared

Code sends, publishes or calls something no record declares.

effect-before-commit

A send or call that would fire before the write is durable.

effect-loop

Effects form a cycle across use cases and reactions.
