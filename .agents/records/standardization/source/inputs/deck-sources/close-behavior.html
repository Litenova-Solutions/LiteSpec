Recommendations for the Behavior Layer

Most Behavior findings are one pattern: the page, the schema, the template and the checker each hold their own copy of a rule, and the copies have drifted. Fix the pattern, not each instance.

1. Make the checks follow the Links table

requirement-unfulfilled, step-unserved and record-orphaned each read a different set of record types; the audience link is rejected. One link-target table, keyed by record type, drives all of them. Findings 2, 3, 12, 13, 14.

2. Schema first, then provisions

Where a provision says "consumer fails", the schema must require the field. Generate the "Checked by" lists from the schema so they cannot drift. Findings 4, 8, 18, 29, 30, 31.

3. One home for each structured fact

Transitions and data in frontmatter, rendered as tables by the book; the retention schedule generated from data classes; one onFailure shape; suppression in one place. Findings 1, 5, 6, 9.

4. Close the open semantics

Where derived refusals sit in precedence; whether cross tenant scope raises the risk tier; glossary status per layer; a module for platform settings; advisory freshness with its authority. Findings 7, 10, 11, 27, 28.

5. Split the page

1387 lines and 94 provisions. Split by folder home: domain model, use cases, automation, edges and screens, privacy and retention. Move obligations out of Concepts. Findings 16, 17, 35.

6. Fix the vocabulary

Rename the minority meanings of source, calls and owner; one reach vocabulary; document either and manage; make every Reviewed for a question. Findings 15, 20, 21, 22, 23, 24.
