# Support

Read the documentation for this release at [litespec.dev/3.0.0](https://litespec.dev/3.0.0/) and in [docs/README.md](docs/README.md) before opening a request. Search the existing issues first, and include the LiteSpec release and a small reproduction where a tool is involved.

## Where to Go

| Need | Route |
|:---|:---|
| A question about using LiteSpec | [GitHub Discussions](https://github.com/Litenova-Solutions/LiteSpec/discussions) |
| A defect in a page, schema, template, or tool | The [Defect issue form](https://github.com/Litenova-Solutions/LiteSpec/issues/new?template=defect.yml) |
| A change to what the standard requires, permits, or generates | The [Proposal issue form](https://github.com/Litenova-Solutions/LiteSpec/issues/new?template=proposal.yml) |
| A security vulnerability | [SECURITY.md](SECURITY.md), through the private reporting route |

For a question, name the stack and shape the project selects and the command or page you read. For a defect, name the provision ID, page, schema, template, or tool that holds the defect and paste the exact command output. For a proposal, state the constraint first and the proposed change second.

Security reports must follow [SECURITY.md](SECURITY.md), not a public issue.
