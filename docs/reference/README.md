# Overview

Reference pages state the exact values behind the names the rules use: what each term means, which page owns each provision ID, which fields each project file holds, and which URLs the published site serves. Open them for lookup in the middle of other work, not for reading in order. They add no rules of their own; each rule lives on the standards page the value points to.

## Terms and Provisions

- [Glossary](glossary.md): what each LiteSpec term means, with one term per concept.
- [Provisions](provisions.md): every provision ID, each naming one rule, with its heading, owning page, and mark.
- [Finding Codes](finding-codes.md): every finding code the tools emit, with its level, layer, trace, meaning, and fix.

## Files and Contracts

- [Project File](project-file.md): every field of `.litespec/project.yaml`, and what reads each one.
- [Release Manifest](manifest.md): every field of `litespec.manifest.yaml`, and the versions it pins.
- [Record Folders](folders.md): where each record type lives: its folder and file.
- [Formats](formats.md): each file format, who writes it, its envelope, and the schema and command that check it.
- [Published URLs](published-urls.md): every URL the site serves, for agents and people.

## Decisions and Obligations

- [Decision Records](decision-records.md): where each decision record lives, what it holds, and how it changes.
- [Audit Obligations](audit-obligations.md): the external obligations the audit extension satisfies.
