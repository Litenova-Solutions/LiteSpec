# LS2035: Unknown Record Thrown as a Generic Exception

LS2035 reports a generic exception thrown for a null check on a value returned by a repository or session load. An unknown record is a not-found refusal, not a server fault: the generic throw answers with a 500 where the caller expects a 404. Refuse the unknown record instead.

## Reference

### What the Rule Enforces

LS2035 enforces [Map Failures to Statuses in the Global Exception Handler](../../backend/dotnet/api.md#map-failures-to-statuses-in-the-global-exception-handler) (`litespec/backend/dotnet/api#map-failures-to-statuses-in-the-global-exception-handler`). It runs in Application and Infrastructure. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports `throw new InvalidOperationException` or `throw new Exception` where the throw is the first statement under `if (value is null)` or `if (value == null)`, with or without braces, or the right side of `??`. The guarded value is either a local declared from a load call or the load call itself, and the call is a repository or session load: a method whose name starts with `Load` or `Find`, or contains `Lookup`, on a receiver typed `*Repository`, `IDocumentSession`, `IQuerySession`, or `DbContext`. The diagnostic sits on the exception type, and its message names the load method and the exception.

### Failing Example

```csharp
public async Task<Expense> HandleAsync(ExpenseId id, CancellationToken cancellationToken)
{
    var expense = await _expenses.FindByIdAsync(id, cancellationToken);
    return expense ?? throw new InvalidOperationException($"No expense with id '{id}'.");
}
```

### Passing Example

```csharp
public async Task<Expense> HandleAsync(ExpenseId id, CancellationToken cancellationToken)
{
    var expense = await _expenses.FindByIdAsync(id, cancellationToken);
    return expense ?? throw new ExpenseNotFoundException($"No expense with id '{id}'.");
}
```

### How to Fix

Throw the module's not-found refusal for the record, in the `{DomainType}{Reason}Exception` form with its stable code, instead of the generic exception.

## Notes

### What the Rule Ignores

Any other thrown type never reports. A required load such as `GetByIdAsync` never reports: it refuses itself, so the name test of `Load`, `Find`, and `Lookup` skips it. A load through a local helper, an in-memory find such as `List<T>.Find`, and a local assigned after its declaration never report: the rule reads the declaration initializer of a local, or the call itself, on a repository or session. An inverted check such as `is not null` with an `else` throw, and a compound condition, never report. The rule does not run outside Application and Infrastructure.
