# LS5005: Runtime Value Differs from Its Record

LS5005 reports a hand-written runtime value that differs from what its record states. An event `Classification` and an exception `Code` copy values their records already state, and a hand-written copy drifts from the record it copies; the generator writes these values from the records instead.

## Reference

### What the Rule Enforces

LS5005 enforces [Generate Runtime Values from the Records](../../packs/dotnet/stack.md#generate-runtime-values-from-the-records) (`litespec/packs/dotnet/stack#generate-runtime-values-from-the-records`). It runs in Domain only. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

A domain event declaring `Classification` with a value other than its event identifier reports. So does a rule exception declaring `Code` with a value other than the `code` of the refusal result its rule names. The diagnostic sits on the member name.

### Failing Example

```csharp
/// <implements>domain-event/expense.submitted</implements>
public sealed partial record ExpenseSubmittedDomainEvent(ExpenseId ExpenseId, Money Amount) : IDomainEvent
{
    public const string Classification = "domain-event/expense.placed";
}
```

### Passing Example

```csharp
/// <implements>domain-event/expense.submitted</implements>
public sealed partial record ExpenseSubmittedDomainEvent(ExpenseId ExpenseId, Money Amount) : IDomainEvent;
```

### How to Fix

Delete the hand-written value and declare the type `partial` so the generator writes the value from the record, or correct the value to match the record. A code fix deletes the hand-written value that differs from the record, titled with the value the record states when the record resolves, with Fix All. Deleting a hand-written value that equals the record is a code fix for LS5006.

## Notes

### What the Rule Ignores

A value equal to its record never reports. Neither does an event or exception with no mark, or with a mark naming no record; `litespec model check` owns those findings. An exception whose rule names no refusal result with a `code` never reports either.

The rule stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error. It does not run outside Domain.

### Severity

The rule reports an error. A finding that a live waiver covers stays silent, and an `.editorconfig` entry for the rule id overrides the computed severity.
