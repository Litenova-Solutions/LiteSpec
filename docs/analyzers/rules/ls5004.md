# LS5004: Mark Uses the Undeclared Style

LS5004 reports a mark written in the style the project did not declare. A project writes all its marks in one style, XML documentation tags or attributes; two styles in one project send each search to half the code.

## Reference

### What the Rule Enforces

LS5004 enforces [Write Each Mark in the Declared Style](../../backend/dotnet/stack.md#write-each-mark-in-the-declared-style) (`litespec/backend/dotnet/stack#write-each-mark-in-the-declared-style`). It runs in every layer, on every marked code element and test. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

An `implements` or `proves` documentation tag reports when the project declares `attribute`. An `Implements` or `Proves` attribute reports when the project declares `xml`. The Claimwick product declares `marks: xml`, so its marks are documentation tags. The diagnostic sits on the mark.

### Failing Example

```csharp
[Implements("use-case/spending.submit-expense")]
internal sealed class SubmitExpenseCommandHandler(...)
    : ICommandHandler<SubmitExpenseCommand, SubmitExpenseCommandResult>
{
    // Loads the expense, submits it, stages it, and returns the result.
}
```

### Passing Example

```csharp
/// <implements>use-case/spending.submit-expense</implements>
internal sealed class SubmitExpenseCommandHandler(...)
    : ICommandHandler<SubmitExpenseCommand, SubmitExpenseCommandResult>
{
    // Loads the expense, submits it, stages it, and returns the result.
}
```

### How to Fix

Rewrite the mark in the declared style. A code fix converts the mark to the declared style, with Fix All.

## Notes

### What the Rule Ignores

A mark written in the declared style never reports. The rule reads C# only; frontend `litespec` constants are checked by `litespec model check`.

The rule stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error.

### Severity

The rule reports an error. A finding that a live waiver covers stays silent, and an `.editorconfig` entry for the rule id overrides the computed severity.
