# LS2005: Handler Name Lacks Its Command or Query Suffix

LS2005 reports a handler whose name does not say whether its use case writes or reads. Every handler runs a use case that either writes or reads, and its name says which, so the model builder can tell a write from a read by the file name.

## Reference

### What the Rule Enforces

LS2005 enforces [Use architectural suffixes](../../workspace/naming.md#use-architectural-suffixes) (`litespec/workspace/naming#use-architectural-suffixes`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A class implementing an interface named `ICommandHandler` reports unless its name ends in `CommandHandler`, and a class implementing an interface named `IQueryHandler` reports unless its name ends in `QueryHandler`. The diagnostic sits on the type name, and its message names the contract and the required suffix.

### Failing Example

```csharp
internal sealed class PlaceOrderUseCase : ICommandHandler<PlaceOrderCommand, int>
{
}
```

### Passing Example

```csharp
internal sealed class PlaceOrderCommandHandler : ICommandHandler<PlaceOrderCommand, int>
{
}
```

### How to Fix

End the class name in `CommandHandler` for a command and in `QueryHandler` for a query, keeping the use-case prefix the file name carries.

## Notes

### What the Rule Ignores

A class implementing neither contract never reports, even one named to end in `Handler`, and interfaces are out of scope. The rule does not run in Domain or WebApi.
