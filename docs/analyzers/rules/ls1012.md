# LS1012: Identifier Is Not a Strongly Typed Value

A raw `Guid` fits every identity slot, so one record's identity flows into another record's slot with no compiler complaint. A strongly typed identifier makes that mistake uncompilable. LS1012 reports an identifier in Domain that is not a strongly typed value.

## Reference

### What the Rule Enforces

LS1012 enforces [Use strongly typed version 7 identifiers](../../backend/dotnet/domain.md#use-strongly-typed-version-7-identifiers) (`litespec/backend/dotnet/domain#use-strongly-typed-version-7-identifiers`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A struct whose name ends in `Id` reports unless it is a `readonly record struct` that wraps exactly one `Guid` field and declares no implicit conversion. It also reports `AggregateRoot<Guid>` and `Entity<Guid>`, where the raw `Guid` serves directly as the identity, and a malformed identity type used as the `AggregateRoot` or `Entity` type argument. The diagnostic sits on the identifier, or on the base type in `AggregateRoot<Guid>` and `Entity<Guid>`.

### Failing Example

```csharp
public record struct OrderId(Guid Value);
```

### Passing Example

```csharp
public readonly record struct OrderId(Guid Value);
```

### How to Fix

Declare the identifier as a `readonly record struct` wrapping one `Guid` with no implicit conversion, use it as the `AggregateRoot` or `Entity` type argument, and pass version 7 values in from the caller.

## Notes

### What the Rule Ignores

A well-formed identifier never reports, and neither does an explicit conversion. The rule does not run outside Domain.
