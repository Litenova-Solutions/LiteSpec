# LS2022: Event Published by User Code

LS2022 reports user code that names the event mediator or an event publisher. The pipeline publishes each module event and each outbound integration event a use case raises, in the same commit; a handler that publishes on its own sends an event the record never declared, outside that commit.

## Reference

### What the Rule Enforces

LS2022 enforces [Stage Declared Module and Integration Events in the Commit](../../backend/application.md#stage-declared-module-and-integration-events-in-the-commit) (`litespec/backend/application#stage-declared-module-and-integration-events-in-the-commit`). It runs in every layer except Test. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A name in the modules project reports when it resolves to the type `IEventMediator`, or to a type whose name ends in `EventPublisher`. The check covers every type in the project, endpoints, reactions, and jobs included. The diagnostic sits on the name, and its message names the type.

### Failing Example

```csharp
namespace Claimwick.Spending.Application.Expenses.ApproveExpense;

internal sealed class SubmitPayoutOnExpenseApprovedHandler
    : IEventHandler<ExpenseApprovedDomainEvent>
{
    private readonly IEventMediator _events;

    public SubmitPayoutOnExpenseApprovedHandler(IEventMediator events)
    {
        _events = events;
    }
}
```

with the file in `Spending/Application/Expenses/ApproveExpense/`. The reaction publishes an event itself, so the event it sends is not the one the approval raised.

### Passing Example

```csharp
namespace Claimwick.Spending.Application.Expenses.ApproveExpense;

internal sealed class ApproveExpenseCommandHandler
{
    private readonly IExpenseRepository _expenses;

    public ApproveExpenseCommandHandler(IExpenseRepository expenses)
    {
        _expenses = expenses;
    }

    public void Handle(ApproveExpenseCommand command)
    {
    }
}
```

with the file in `Spending/Application/Expenses/ApproveExpense/`. The aggregate raises `ExpenseApprovedDomainEvent` from its marked method, and the pipeline publishes the `expense-approved` module event that translates it, in the same commit.

### How to Fix

Raise a domain event from the aggregate method that performs the act, and declare the module event or integration event that translates it. Remove the event mediator and the event publisher from the type. A reaction or job that needs to send work names a use case message, not an event.

## Notes

### What the Rule Ignores

A name appearing only in a using directive or a documentation comment never reports. The Platform, which holds the publishing pipeline, is out of scope, with the shared kernel of a one-modules-project solution. The rule does not run in a Test file or in a file the layer rules cannot place. A command handler taking the event mediator is reported by this rule and by [LS2021](ls2021.md), so both findings name the same fix.
