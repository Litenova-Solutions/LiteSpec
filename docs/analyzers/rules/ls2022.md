# LS2022: Event Published by User Code

## Intent

LS2022 is a compiler check that reports user code naming the event mediator or an event publisher, because the pipeline publishes each outbound integration event a use case raises, and a handler that publishes on its own sends an event the record never declared. This page states what the rule reports, where the error sits, and how to let the raised domain event carry the integration event.

## Reference

### What the Rule Enforces

LS2022 enforces [Emit Declared Integration Events After Commit](../../backend/application.md#emit-declared-integration-events-after-commit) (`litespec/backend/application#emit-declared-integration-events-after-commit`). It runs in every layer except Test. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a name in the modules project that resolves to the type `IEventMediator`, or to a type whose name ends in `EventPublisher`. The check covers every type in the project, endpoints, reactions and jobs included. The diagnostic sits on the name, and its message names the type.

### Failing Example

```csharp
namespace Claimwick.Spending.Expenses.UseCases.ApproveExpense;

internal sealed class SubmitPayoutOnExpenseApprovedHandler(IEventMediator events)
    : IEventHandler<ExpenseApprovedEvent>
{
}
```

with the file in `Spending/Expenses/UseCases/ApproveExpense/Application/`. The reaction publishes an event itself, so the integration event it sends is not the one the approval raised.

### Passing Example

```csharp
namespace Claimwick.Spending.Expenses.UseCases.ApproveExpense;

internal sealed class ApproveExpenseCommandHandler(IExpenseRepository expenses)
{
    public void Handle(ApproveExpenseCommand command)
    {
    }
}
```

with the file in `Spending/Expenses/UseCases/ApproveExpense/Application/`. The aggregate raises `ExpenseApprovedEvent` from its marked method, and the pipeline publishes the `expense-approved` integration event that translates it, in the same commit.

### How to Fix

Raise a domain event from the aggregate method that performs the act, and declare the integration event that translates it. Remove the event mediator and the event publisher from the type. A reaction or job that needs to send work names a use case message, not an event.

## Notes

### What the Rule Ignores

The rule does not report a name written only in a using directive or a documentation comment. It does not report the shared kernel, which holds the publishing pipeline. It does not run in a Test file or in a file the layer rules cannot place. A command handler that takes the event mediator is reported by this rule and by [LS2021](ls2021.md), so both findings name the same fix.
