# LS2037: Identity Value Read in a Queryable Expression

LS2037 reports a read of the document's own identity value inside a queryable expression. The document store cannot translate the member chain on its identity member, so the read fails at run time. Compare the identifier itself, or page in memory.

## Reference

### What the Rule Enforces

LS2037 enforces [Compare Typed Identifiers by Their Underlying Values in Queries](../../backend/dotnet/persistence.md#compare-typed-identifiers-by-their-underlying-values-in-queries) (`litespec/backend/dotnet/persistence#compare-typed-identifiers-by-their-underlying-values-in-queries`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a member access `<parameter>.Id.Value` where the lambda parameter's `Id` member is typed as a typed identifier: a struct named `*Id` or implementing `IStronglyTypedId`. The access sits inside a lambda passed directly to a queryable operator: a method of `Queryable`, or a call on an `IQueryable` receiver. The diagnostic sits on the `Value` name, and its message names the document and the identifier.

### Failing Example

```csharp
public IQueryable<Expense> Handle(IQueryable<Expense> query, Guid cursor)
{
    return query.Where(expense => expense.Id.Value.CompareTo(cursor) < 0);
}
```

### Passing Example

```csharp
public IQueryable<Expense> Handle(IQueryable<Expense> query, ExpenseId id)
{
    return query.Where(expense => expense.Id == id);
}
```

### How to Fix

Compare the identifier itself inside the expression, or page the documents in memory where the comparison needs the underlying value.

## Notes

### What the Rule Ignores

A value read on any other member never reports: `expense.Owner.Value` reads a non-identity member the store translates. A value read in memory never reports: the lambda must convert to an expression tree passed directly to a queryable operator, so a lambda passed to an `Enumerable` operator or to any other method taking an expression stays quiet. The rule does not run in Domain, Ports, or WebApi.
