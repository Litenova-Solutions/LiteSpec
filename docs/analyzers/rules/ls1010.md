# LS1010: Repository Exposes a Query Surface

LS1010 reports a repository interface in Domain that exposes a query surface. A repository loads and writes one aggregate, and nothing more. A query surface such as `IQueryable` or a database session would let any caller compose queries that bypass the rules the aggregate protects.

## Reference

### What the Rule Enforces

LS1010 enforces [Keep repository interfaces in Domain](../../packs/dotnet/domain.md#keep-repository-interfaces-in-domain) (`litespec/packs/dotnet/domain#keep-repository-interfaces-in-domain`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

An interface whose name ends in `Repository` reports when it is generic over a type parameter its members use. It also reports when a member exposes a query surface: `IQueryable`, a type derived from it, a member type whose name ends in `Session`, `DbContext`, or `DbSet` without deriving the project's `AggregateRoot<>`, or an `Expression<Func<...>>` parameter. The diagnostic sits on the interface name for a generic surface, and on the offending member type for any other breach.

### Failing Example

```csharp
public interface IOrderRepository
{
    IQueryable<Order> Query();
}
```

### Passing Example

```csharp
public interface IOrderRepository
{
    Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken);
}
```

### How to Fix

Return only aggregates and Domain types from the repository, and move query composition into a query handler that reads through `IQuerySession`.

## Notes

### What the Rule Ignores

Interfaces whose names do not end in `Repository` never report, and neither do members returning aggregates and Domain types such as `Task<Order?> FindAsync(OrderId id, CancellationToken cancellationToken)`. An aggregate deriving `AggregateRoot<>` never breaches the name test, even when its name ends in `Session`, `DbContext`, or `DbSet`. The rule does not run outside Domain.
