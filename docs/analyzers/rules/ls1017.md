# LS1017: Validated Value Type Offers No Non-Throwing Parse

LS1017 reports a typed identifier or value type whose constructor throws on invalid input and which offers no non-throwing parse. The serializer and the API boundary read input nobody has validated yet, so without a `TryParse` they can only call the throwing constructor and turn bad input into an unhandled throw.

## Reference

### What the Rule Enforces

LS1017 enforces [Offer a Non-Throwing Parse on Validated Value Types](../../backend/dotnet/domain.md#offer-a-non-throwing-parse-on-validated-value-types) (`litespec/backend/dotnet/domain#offer-a-non-throwing-parse-on-validated-value-types`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a struct, record or plain, whose explicit instance constructor holds a throw statement or throw expression, and which declares no static `TryParse`, `TryCreate`, or `TryFrom` that returns `bool` with an `out` parameter of the type. The diagnostic sits on the type name, and its message names the type.

### Failing Example

```csharp
public readonly record struct ExpenseTitle
{
    public ExpenseTitle(string value)
    {
        if (string.IsNullOrWhiteSpace(value))
        {
            throw new ArgumentException("A title is required.", nameof(value));
        }

        Value = value;
    }

    public string Value { get; }
}
```

### Passing Example

```csharp
public readonly record struct ExpenseTitle
{
    public ExpenseTitle(string value)
    {
        if (string.IsNullOrWhiteSpace(value))
        {
            throw new ArgumentException("A title is required.", nameof(value));
        }

        Value = value;
    }

    public string Value { get; }

    public static bool TryParse(string? value, out ExpenseTitle result)
    {
        if (string.IsNullOrWhiteSpace(value))
        {
            result = default;
            return false;
        }

        result = new ExpenseTitle(value);
        return true;
    }
}
```

### How to Fix

Add a static `TryParse` that returns `false` with a default `out` value on invalid input, so the serializer and the API boundary read bad input without throwing.

## Notes

### What the Rule Ignores

A struct whose constructors never throw never reports, and neither does a class, however its constructor validates. A `TryParse` that returns no `bool`, or takes no `out` parameter of the type, does not count as the parse. A throw reached only through a helper the constructor calls never reports: the rule reads explicit constructor bodies. The rule does not run outside Domain.
