# LS2021: Message Sent Outside an Entry Point

LS2021 reports a type that holds a command, query, or event mediator without being an entry point. A use case message starts work, and only three entry points send one: an endpoint, a reaction, and a job. A handler that sends a message from the middle of its own run chains use cases together where nobody declared the chain.

## Reference

### What the Rule Enforces

LS2021 enforces [Keep Command Handlers to Load, Call and Stage](../../backend/application.md#keep-command-handlers-to-load-call-and-stage) (`litespec/backend/application#keep-command-handlers-to-load-call-and-stage`). It runs in Domain, Application, and Infrastructure. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A constructor parameter, field, or property typed as `ICommandMediator`, `IQueryMediator`, or `IEventMediator` reports when its holder is not an entry point. An entry point is a type implementing `IEventHandler<T>` (a reaction), a type deriving from `BackgroundService` or whose name ends in `Job` (a job), or a type whose name ends in `Endpoint` (an endpoint). The diagnostic sits on the mediator type, and its message names the holding type and the mediator.

### Failing Example

```csharp
namespace Claimwick.Spending.Expenses.UseCases.ApproveExpense;

internal sealed class ApproveExpenseCommandHandler
{
    private readonly ICommandMediator _commands;

    public ApproveExpenseCommandHandler(ICommandMediator commands)
    {
        _commands = commands;
    }
}
```

with the file in `Spending/Expenses/UseCases/ApproveExpense/Application/`. A command handler loads an expense, calls one act on it, and stages it. The follow-on command belongs to a reaction that runs after the commit.

### Passing Example

```csharp
namespace Claimwick.Spending.Expenses.UseCases.ApproveExpense;

internal sealed class SubmitPayoutOnExpenseApprovedHandler
    : IEventHandler<ExpenseApprovedEvent>
{
    private readonly ICommandMediator _commands;

    public SubmitPayoutOnExpenseApprovedHandler(ICommandMediator commands)
    {
        _commands = commands;
    }
}
```

with the file in `Spending/Expenses/UseCases/ApproveExpense/Application/`. The reaction implements `IEventHandler<T>`, so it is an entry point and may hold the command mediator. It sends the one use case message it runs.

### How to Fix

Remove the mediator from the type, and send the follow-on message from a reaction on the event the handler raised. The reaction sits in the `Application/` folder of the use case it runs, and it holds the command mediator. A job that runs a command over many records is an entry point as well.

## Notes

### What the Rule Ignores

A method parameter that is not a constructor parameter never reports. A method taking a mediator as an argument is not checked. Types in the Platform, which composes the pipeline and holds the mediators by design, are out of scope, with types in the shared kernel of a one-modules-project solution. The rule does not run in a Test file or in a file the layer rules cannot place. The mediator itself is checked by [LS2022](ls2022.md) where it publishes events.
