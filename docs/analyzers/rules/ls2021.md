# LS2021: Message Sent Outside an Entry Point

LS2021 reports a type that holds a command, query, or event mediator its role may not hold. A use case message starts work: a handler sends another module's public query through the query mediator, and a reaction or a job sends the follow-on command. A mediator held anywhere else chains use cases together where nobody declared the chain.

## Reference

### What the Rule Enforces

LS2021 enforces [Keep Command Handlers to Load, Call and Stage](../../backend/application.md#keep-command-handlers-to-load-call-and-stage) (`litespec/backend/application#keep-command-handlers-to-load-call-and-stage`). It runs in Domain, Application, and Infrastructure. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A constructor parameter, field, or property typed as `ICommandMediator` reports unless its holder is a reaction or a job: a type implementing `IEventHandler<T>`, or a type deriving from `BackgroundService` or whose name ends in `Job` or `Worker`. One typed as `IQueryMediator` reports unless its holder is a command or query handler, a reaction, or a job: a handler is a type whose name ends in `CommandHandler` or `QueryHandler`, or that implements `ICommandHandler` or `IQueryHandler`. One typed as `IEventMediator` reports in every module type: only the platform publishes events. The diagnostic sits on the mediator type, and its message names the holding type, the mediator, and which roles may hold it.

### Failing Example

```csharp
namespace Claimwick.Spending.Application.Expenses.ApproveExpense;

internal sealed class ApproveExpenseCommandHandler
{
    private readonly ICommandMediator _commands;

    public ApproveExpenseCommandHandler(ICommandMediator commands)
    {
        _commands = commands;
    }
}
```

with the file in `Spending/Application/Expenses/ApproveExpense/`. A command handler loads an expense, calls one act on it, and stages it. The follow-on command belongs to a reaction that runs after the commit.

### Passing Example

```csharp
namespace Claimwick.Spending.Application.Expenses.ApproveExpense;

internal sealed class SubmitPayoutOnExpenseApprovedHandler
    : IEventHandler<ExpenseApprovedDomainEvent>
{
    private readonly ICommandMediator _commands;

    public SubmitPayoutOnExpenseApprovedHandler(ICommandMediator commands)
    {
        _commands = commands;
    }
}
```

with the file in `Spending/Application/Expenses/ApproveExpense/`. The reaction implements `IEventHandler<T>`, so it may hold the command mediator. It sends the one use case message it runs.

A handler holding the query mediator passes as well:

```csharp
namespace Claimwick.Reporting.Application.ListReimbursedExpenses;

internal sealed class ListReimbursedExpensesQueryHandler
{
    private readonly IQueryMediator _queries;

    public ListReimbursedExpensesQueryHandler(IQueryMediator queries)
    {
        _queries = queries;
    }
}
```

with the file in `Reporting/Application/ListReimbursedExpenses/`. The handler asks another module's public query through the query mediator, which its record declares.

### How to Fix

Keep the query send in the handler: a handler holds the query mediator to ask another module's public query. Move a command send to a reaction on the event the handler raised. The reaction sits in the `Application/` folder of the use case it runs, and it holds the command mediator. A job that runs a command over many records holds the command mediator as well. Nothing outside the platform holds the event mediator.

## Notes

### What the Rule Ignores

A method parameter that is not a constructor parameter never reports. A method taking a mediator as an argument is not checked. An endpoint dispatches its own use case message through a method parameter, so it holds no mediator; an endpoint that holds a mediator as a constructor parameter, field, or property reports like any other type. Types in the Platform, which composes the pipeline and holds the mediators by design, are out of scope, with types in the shared kernel of a one-modules-project solution. The rule does not run in a Test file or in a file the layer rules cannot place. The mediator itself is checked by [LS2022](ls2022.md) where it publishes events.
