# LS1006: Domain Exception Is Misnamed or Open

## Intent

LS1006 is a compiler check that reports a DomainException subclass in Domain, the project that holds business rules, that is not sealed or whose name does not end in Exception, which hides which business rule failed. This page states what the rule reports, where the error sits, and how to name and seal the exception.

## Reference

### What the Rule Enforces

LS1006 enforces [Reject business violations with Domain exceptions](../../backend/dotnet/domain.md#reject-business-violations-with-domain-exceptions) (`litespec/backend/dotnet/domain#reject-business-violations-with-domain-exceptions`). It runs in Domain only. Its category is `LiteSpec.Domain`. It reports an error and is enabled by default, as the [Analyzers overview](../README.md) describes.

### What the Rule Reports

The rule reports a non-abstract `DomainException` subclass, direct or indirect, that is not sealed or whose name does not end in `Exception`. One type gets one diagnostic even when both checks fail. The diagnostic sits on the exception name.

### Failing Example

```csharp
public class OrderRuleFailure : DomainException
{
    public OrderRuleFailure() : base("Broken.") { }
}
```

### Passing Example

```csharp
public abstract class OrderException(string message) : DomainException(message);

public sealed class OrderAlreadyPlacedException() : OrderException("The order is already placed.");
```

### How to Fix

Mark the leaf exception `sealed` and name it `{DomainType}{Reason}Exception`, keeping shared behavior in an abstract intermediate base.

## Notes

### What the Rule Ignores

The rule does not report abstract intermediate exception bases or sealed leaves named `{DomainType}{Reason}Exception`. It does not run outside Domain.
