# LS1006: Domain Exception Is Misnamed or Open

LS1006 reports a `DomainException` subclass in Domain that is not sealed or whose name does not end in `Exception`. A rule exception tells the caller which business rule failed, and its name is how the caller recognizes it.

## Reference

### What the Rule Enforces

LS1006 enforces [Reject business violations with Domain exceptions](../../backend/dotnet/domain.md#reject-business-violations-with-domain-exceptions) (`litespec/backend/dotnet/domain#reject-business-violations-with-domain-exceptions`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A non-abstract `DomainException` subclass, direct or indirect, reports when it is not sealed or its name does not end in `Exception`. One type gets one diagnostic even when both checks fail. The diagnostic sits on the exception name.

### Failing Example

```csharp
public class OrderRuleFailure : DomainException
{
    public OrderRuleFailure() : base("Broken.") { }
}
```

### Passing Example

```csharp
public abstract class OrderException(string message) : DomainException(message);

public sealed class OrderAlreadyPlacedException() : OrderException("The order is already placed.");
```

### How to Fix

Seal the leaf exception and name it `{DomainType}{Reason}Exception`, moving shared behavior into an abstract intermediate base.

## Notes

### What the Rule Ignores

Abstract intermediate exception bases never report, and neither do sealed leaves already named `{DomainType}{Reason}Exception`. The rule does not run outside Domain.
