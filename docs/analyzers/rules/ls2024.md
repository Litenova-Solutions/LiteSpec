# LS2024: Module Holds Platform-Owned Capability Code

LS2024 reports serializer, store, guard, or converter code inside a module that the platform provides. A module plugs into a platform capability by contributing data to the platform registry: the platform builds the one serializer, the one guard evaluation, and the one converter set, and no module copies them.

## Reference

### What the Rule Enforces

LS2024 enforces [Plug Modules into the Platform Through Contributions](../../packs/dotnet/architecture.md#plug-modules-into-the-platform-through-contributions) (`litespec/packs/dotnet/architecture#plug-modules-into-the-platform-through-contributions`). It runs in module files of every production layer. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A name in a module file reports when it resolves to a store or serializer setup type: `StoreOptions`, `DocumentStore`, `DbContextOptionsBuilder`, or `NpgsqlDataSourceBuilder`. A class in a module file reports when it derives from a guard contract (`DeclarationGuard`, `ICommandGuard`, `IQueryGuard`) or from the `JsonConverter` base. The diagnostic sits on the name or the class name, and its message names the contribution to write instead.

### Failing Example

```csharp
namespace Claimwick.Spending.Infrastructure.Persistence;

internal static class SpendingStoreSetup
{
    internal static StoreOptions Options()
    {
        var options = new StoreOptions();
        return options;
    }
}
```

The module configures its own store instead of contributing its stored types through its entry type.

### Passing Example

```csharp
namespace Claimwick.Spending.Infrastructure.Persistence;

internal sealed class ExpenseRepository : IExpenseRepository
{
    private readonly IDocumentSession _session;

    public ExpenseRepository(IDocumentSession session)
    {
        _session = session;
    }
}
```

with the file in `Spending/Infrastructure/Persistence/`. The repository uses the session the platform built from the module's contributed stored types; the module configures no store of its own.

### How to Fix

Delete the copy and contribute through the module entry type: stored types and discriminators to the persistence registry, policies to access, and routes to HTTP discovery. Declare a shared access condition as a policy in the use case `AuthorizationDefinition` instead of writing a guard.

## Notes

### What the Rule Ignores

Store use, such as a document session in a repository, never reports: only setup does. A name in a Test file, in a Platform, Kernel, or host file, or in a file the layer rules cannot place, never reports. Endpoint-discovery code has no cheap name the rule could match, so the rule does not check it; review covers that part of the provision.
