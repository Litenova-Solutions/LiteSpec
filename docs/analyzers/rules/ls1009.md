# LS1009: Domain Reads a Nondeterministic Value

LS1009 reports a read in Domain of the clock, randomness, or a new identifier. Such a read answers differently on every call, so no test can repeat it. Domain decisions stay deterministic by taking such values from their callers instead of reading them.

## Reference

### What the Rule Enforces

LS1009 enforces [Pass nondeterministic values into Domain](../../backend/domain.md#pass-nondeterministic-values-into-domain) (`litespec/backend/domain#pass-nondeterministic-values-into-domain`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports reads of `DateTime.Now`, `DateTime.UtcNow`, `DateTime.Today`, `DateTimeOffset.Now`, `DateTimeOffset.UtcNow`, `TimeProvider.System`, `Environment.TickCount`, `Environment.TickCount64`, `Random.Shared`, `Guid.NewGuid`, `Guid.CreateVersion7`, `Stopwatch.GetTimestamp`, `Stopwatch.StartNew`, any `RandomNumberGenerator` call, and `new Random()`. The diagnostic sits on the member name, on the invoked method name, or on the type in `new Random()`.

### Failing Example

```csharp
public DateTime Stamp()
{
    return DateTime.UtcNow;
}
```

### Passing Example

```csharp
public DateTime Stamp(DateTime utcNow)
{
    return utcNow;
}
```

### How to Fix

Take time, randomness, and new identifiers as arguments from the caller, and create version 7 identifiers with `Guid.CreateVersion7` in the calling layer.

## Notes

### What the Rule Ignores

Values arriving as arguments never report. Deterministic members such as `DateTime.MinValue`, `Guid.Empty`, and `Guid.Parse` pass, as do instance calls on an injected clock such as `clock.GetUtcNow()` and names inside `nameof`. The rule does not run outside Domain.
