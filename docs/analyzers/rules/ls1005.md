# LS1005: Domain Throws a Non-Domain Exception

LS1005 reports a throw in Domain of any exception outside the `DomainException` subclasses. When Domain rejects a business rule, the caller needs a stable failure code and a business meaning to react to, and a plain .NET exception carries neither.

## Reference

### What the Rule Enforces

LS1005 enforces [Reject business violations with Domain exceptions](../../packs/dotnet/domain.md#reject-business-violations-with-domain-exceptions) (`litespec/packs/dotnet/domain#reject-business-violations-with-domain-exceptions`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A `throw` of any exception outside the `DomainException` subclasses reports. The diagnostic sits on the thrown expression, for example on `new InvalidOperationException()`, and its message names the thrown type. A `throw` of a conditional, switch expression, or null-coalescing expression reports at each branch whose exception is not allowed.

### Failing Example

```csharp
public void Place()
{
    throw new InvalidOperationException();
}
```

### Passing Example

```csharp
public void Place(bool placed)
{
    if (placed)
    {
        throw new OrderAlreadyPlacedException();
    }
}
```

### How to Fix

Throw a `DomainException` subclass named `{DomainType}{Reason}Exception` for the rejected business rule, keeping `ArgumentException` for argument guards.

## Notes

### What the Rule Ignores

A throw of a `DomainException` subclass never reports, and neither does an argument guard throwing `ArgumentException` or one of its subclasses, a throw of `UnreachableException`, a bare `throw;`, or a throw of a caught variable. The rule does not run outside Domain.
