# LS2028: Module Exposes a Public Type Outside Contracts

LS2028 reports a public type in a module project outside its `Contracts/` folder and its module entry type. With one project per module, visibility is the module boundary: only `Contracts/` and the entry type are public, so the compiler refuses any reference into module internals.

## Reference

### What the Rule Enforces

LS2028 enforces [Expose Only Contracts and the Entry Point](../../backend/dotnet/architecture.md#expose-only-contracts-and-the-entry-point) (`litespec/backend/dotnet/architecture#expose-only-contracts-and-the-entry-point`). It runs in one-project-per-module compilations, in every production layer. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A top-level type in a module project reports when it is effectively public and its file sits outside the module `Contracts/` folder and is not the `{Module}Module.cs` entry file. The diagnostic sits on the type name, and its message names the entry type that stays public beside `Contracts/`.

### Failing Example

```csharp
namespace Claimwick.Spending.Domain.Expense;

public sealed class Expense : AggregateRoot<ExpenseId>
{
}
```

The aggregate root is public, so another module could reference the module's internals past its contracts.

### Passing Example

```csharp
namespace Claimwick.Spending.Domain.Expense;

internal sealed class Expense : AggregateRoot<ExpenseId>
{
}
```

The root stays internal, and other modules reach the module only through its contracts.

### How to Fix

Make the type internal. A type other modules use moves to the module `Contracts/` folder; the module entry type keeps its public registration surface.

## Notes

### What the Rule Ignores

A type in `Contracts/`, the module entry type, an internal type, and a nested type inside an internal type never report. The rule does not run in one-modules-project compilations, where `LS2020` keeps the boundary, nor in Kernel, Platform, host, or Test projects.
