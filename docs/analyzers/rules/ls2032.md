# LS2032: Queryable Contains over Typed Identifiers

LS2032 reports a `Contains` over typed identifiers inside a queryable expression. The database driver cannot send a typed identifier collection as a parameter, so the read fails at run time. Compare the underlying value instead.

## Reference

### What the Rule Enforces

LS2032 enforces [Compare Typed Identifiers by Their Underlying Values in Queries](../../packs/dotnet/persistence.md#compare-typed-identifiers-by-their-underlying-values-in-queries) (`litespec/packs/dotnet/persistence#compare-typed-identifiers-by-their-underlying-values-in-queries`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports `Enumerable.Contains` in its static or extension form, or an instance `Contains` with one argument, where the checked element type is a typed identifier: a struct named `*Id` or implementing `IStronglyTypedId`. The call sits inside a lambda passed directly to a queryable operator: a method of `Queryable`, or a call on an `IQueryable` receiver. The diagnostic sits on the `Contains` name, and its message names the collection and the identifier.

### Failing Example

```csharp
public IQueryable<Expense> Handle(IQueryable<Expense> query, List<ExpenseId> ids)
{
    return query.Where(expense => ids.Contains(expense.Id));
}
```

### Passing Example

```csharp
public IQueryable<Expense> Handle(IQueryable<Expense> query, IEnumerable<Guid> values)
{
    return query.Where(expense => values.Contains(expense.Id.Value));
}
```

### How to Fix

Project the identifiers to their underlying values before the query, and compare the member's value inside the expression.

## Notes

### What the Rule Ignores

A `Contains` over any other element type never reports, and neither does an equality check between two typed identifiers. A `Contains` in memory never reports: the lambda must convert to an expression tree passed directly to a queryable operator, so a lambda passed to an `Enumerable` operator or to any other method taking an expression stays quiet. The rule does not run in Domain, Ports, or WebApi.
