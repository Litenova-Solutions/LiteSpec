# LS2013: Audit Value Read from the Message in the Handler

LS2013 reports a command handler that sets an audit value the pipeline already records. When the command message already carries the value, it belongs beside the message, where the pipeline records it before the handler runs, on every outcome including a denial; a handler that adds it again repeats that work.

## Reference

### What the Rule Enforces

LS2013 enforces [Declare audit values beside the message](../../backend/application.md#declare-the-audit-target-and-reason-beside-the-message) (`litespec/backend/application#declare-the-audit-target-and-reason-beside-the-message`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A call to `WithTarget` or `WithReason` on a receiver of type `IAuditScope` reports inside a command handler: a class whose name ends in `CommandHandler` or that implements `ICommandHandler`.

The call reports when every argument reads only the handler message parameter, constants, and string formatting, and at least one argument reads the message. The diagnostic sits on the invoked member name, and its message names the handler and the call.

### Failing Example

```csharp
internal sealed class RenewLoanCommandHandler
{
    public void Handle(RenewLoanCommand command, IAuditScope audit)
    {
        audit.WithTarget(command.LoanId);
        audit.WithReason($"Renewed by {command.ReaderName}");
    }
}
```

### Passing Example

```csharp
internal sealed class RenewLoanCommandHandler(ILoanRepository loanRepository)
{
    public void Handle(RenewLoanCommand command, IAuditScope audit)
    {
        var loan = loanRepository.GetById(command.LoanId);
        var renewalId = Guid.NewGuid();
        audit.WithTarget(loan.Id);
        audit.WithTarget(renewalId);
    }
}
```

### How to Fix

Move the target and reason beside the command, so the pipeline records them on every outcome, including a denial. Keep in the handler only a generated identity or a reason composed from loaded state.

## Notes

### What the Rule Ignores

An argument that reads a local, a loaded aggregate, or a generated value never reports. Neither does an argument reading only a constant. Calls on any other receiver type, or outside a command handler, are out of scope. The rule does not run in Domain or WebApi.
