# LS1008: Domain Uses Binary Floating Point

Money and exact quantities live in Domain, and binary rounding makes their totals and equality checks quietly wrong. LS1008 reports a `double` or `float` type in Domain, wherever it appears.

## Reference

### What the Rule Enforces

LS1008 enforces [Keep binary floating point out of exact quantities](../../backend/domain.md#keep-binary-floating-point-out-of-exact-quantities) (`litespec/backend/domain#keep-binary-floating-point-out-of-exact-quantities`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports every `double` or `float` type in a field, property, indexer, method return, local function return, delegate, operator, parameter, `foreach` variable, declaration expression, or declaration pattern. Nested uses count as well, such as `List<double>`, `double?`, tuples, and lambda parameters. The diagnostic sits on the floating point type, and its message names the member and the type text.

### Failing Example

```csharp
public sealed class Pricer
{
    public double Total(double rate) => rate;
}
```

### Passing Example

```csharp
public sealed class Pricer
{
    private decimal _total;

    public decimal Total(decimal rate) => rate;
}
```

### How to Fix

Use `decimal` or a value object for monetary amounts, the rates applied to them, and quantities compared for exact equality.

## Notes

### What the Rule Ignores

The rule never reports `decimal` or `var`. It reports no floating point use outside Domain.
