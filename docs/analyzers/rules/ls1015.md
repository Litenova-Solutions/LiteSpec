# LS1015: Non-Root Type Exposes Public Mutation

LS1015 reports a non-root type of an aggregate that exposes a public setter, a public constructor, or a mutable public collection. Only the root changes its aggregate: entities and value objects inside an aggregate offer no public mutation surface of their own.

## Reference

### What the Rule Enforces

LS1015 enforces [Model Child Entities as Sealed Classes](../../packs/dotnet/domain.md#model-child-entities-as-sealed-classes) (`litespec/packs/dotnet/domain#model-child-entities-as-sealed-classes`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A non-root class or struct declared in an aggregate's `Domain/` folder reports when it declares a public setter, a public instance constructor, or a public instance property or field typed as a mutable collection. A setter reports on the `set` accessor; a constructor reports on the constructor; a collection reports on the property or field. The message names the type, the aggregate, and the mutation to remove.

A mutable collection is `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`, `Collection<T>`, `ObservableCollection<T>`, `LinkedList<T>`, `Queue<T>`, `Stack<T>`, the sorted collections, `IList<T>`, `IDictionary<TKey, TValue>`, `ICollection<T>`, `ISet<T>`, and the non-generic `ArrayList` and `Hashtable`. Read-only collections, `IEnumerable<T>`, and immutable collections never report.

### Failing Example

```csharp
namespace Claimwick.Spending.Domain.Expense;

internal sealed class ExpenseLine : Entity<ExpenseLineId>
{
    public ExpenseLine(ExpenseLineId id, Money amount)
        : base(id)
    {
        Amount = amount;
    }

    public Money Amount { get; set; }
}
```

The line exposes a public constructor and a public setter, so any caller builds and changes it without the root.

### Passing Example

```csharp
namespace Claimwick.Spending.Domain.Expense;

internal sealed class ExpenseLine : Entity<ExpenseLineId>
{
    internal ExpenseLine(ExpenseLineId id, Money amount)
        : base(id)
    {
        Amount = amount;
    }

    public Money Amount { get; }
}
```

The constructor is internal, so only the root builds lines, and the amount has no setter.

### How to Fix

Make the constructor internal and remove the setter, exposing collections as `IReadOnlyList<T>` or another read-only shape. The root builds the type through its own factories and changes it through its own methods.

## Notes

### What the Rule Ignores

The aggregate root never reports, and neither do typed identifiers, domain events, exceptions, and interfaces. Records, abstract types, and the root's input types never report for the constructor check: state and closed-set cases and value-object records construct through their positional form. An `init` accessor is not a setter. Arrays never report. A type directly under a module `Domain/` folder, outside every aggregate folder, or outside Domain never reports.
