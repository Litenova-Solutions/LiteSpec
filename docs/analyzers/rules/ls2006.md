# LS2006: Endpoint Name Lacks Its Suffix

LS2006 reports an endpoint whose name lacks the `Endpoint` suffix. An endpoint maps one use case to HTTP, and the suffix lets the model builder find it by its file name.

## Reference

### What the Rule Enforces

LS2006 enforces [Use architectural suffixes](../../workspace/naming.md#use-architectural-suffixes) (`litespec/workspace/naming#use-architectural-suffixes`). It runs in WebApi only. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A class implementing an interface named `IEndpoint` reports unless its name ends in `Endpoint`. The diagnostic sits on the type name.

### Failing Example

```csharp
internal sealed class CreateDraftRoute : IEndpoint
{
}
```

### Passing Example

```csharp
internal sealed class CreateDraftEndpoint : IEndpoint
{
}
```

### How to Fix

Rename the class to end in `Endpoint`, keeping the use-case prefix from the file name.

## Notes

### What the Rule Ignores

Classes implementing no interface named `IEndpoint` never report, and interfaces are out of scope. The rule does not run outside WebApi.
