# LS3003: File Does Not Match Its Primary Type

## Intent

LS3003 is a compiler check that reports a C# file whose name does not match the type it holds, which sends every reader searching for code that lives somewhere unexpected. This page states what the rule reports, where the error sits, and how to align the file with its type.

## Reference

### What the Rule Enforces

LS3003 enforces [Match C# files and primary types](../../backend/dotnet/naming.md#match-c-files-and-primary-types) (`litespec/backend/dotnet/naming#match-c-files-and-primary-types`). It runs in all five projects. Its category is `LiteSpec.Style`. It reports an error and is enabled by default, as the [Analyzers overview](../README.md) describes.

### What the Rule Reports

The rule reports a C# file whose single top-level type has a different name, and every type after the first when a file holds several top-level types. A dotted file name such as `Order.Validation.cs` matches the part before the first dot, generic arity is ignored, and partial declarations of the same type count once. Only types directly in the compilation unit or a namespace count; nested types never do. The diagnostic sits on the type name.

### Failing Example

In a file named `Order.cs`, this type reports:

```csharp
namespace Shop.Domain.Orders;

public sealed class Customer { }
```

### Passing Example

In a file named `Order.cs`, this type passes:

```csharp
namespace Shop.Domain.Orders;

public sealed class Order { }
```

### How to Fix

Give the file the name of its one primary top-level type, or split the file so each top-level type has its own file.

## Notes

### What the Rule Ignores

The rule does not report files with no top-level types. It does not run outside the five projects.
