# LS5002: Mark Names No Usable Record

## Intent

LS5002 is a compiler check that reports a mark naming no record, or a record of a type its code element does not take, because a mark pointing nowhere leaves the element unlinked. This page states what the rule reports, where the error sits, and how to name a record the element takes.

## Reference

### What the Rule Enforces

LS5002 enforces [Point Code and Tests up to Records](../../core/system.md#point-code-and-tests-up-to-records) (`litespec/core/system#point-code-and-tests-up-to-records`). It runs in every layer, on every marked code element and test. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

The rule reports a mark whose identifier matches no record, or matches a record of a type its code element does not take, such as a handler marking a rule. The marks table on the [model page](../../core/model.md#marks) states which record type each kind takes. The diagnostic sits on the mark.

### Failing Example

```csharp
/// <implements>use-case/spending.submit-expences</implements>
internal sealed class SubmitExpenseCommandHandler(...)
    : ICommandHandler<SubmitExpenseCommand, SubmitExpenseCommandResult>
{
    // Loads the expense, submits it, stages it, and returns the result.
}
```

### Passing Example

```csharp
/// <implements>use-case/spending.submit-expense</implements>
internal sealed class SubmitExpenseCommandHandler(...)
    : ICommandHandler<SubmitExpenseCommand, SubmitExpenseCommandResult>
{
    // Loads the expense, submits it, stages it, and returns the result.
}
```

### How to Fix

Name a record of the type the element takes, spelled as the record states it. A code fix corrects a mistyped id, offering the three nearest records of the expected type by edit distance, one action each, with no Fix All.

## Notes

### What the Rule Ignores

The rule does not report an element with no mark; LS5001 owns that finding. It does not report a mark naming a record of the type its element takes. The rule stays silent when no `litespec.project.json` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error.

### Severity

Severity follows the record the mark names: an error when it is approved or reviewed, a warning when it is a draft, and silence when it is retired. A mark naming no record follows its tier and reports as an error. A finding covered by an open known gap or an in-date approved deviation stays silent. While `check.phase` is `frozen`, a finding on a test reports as a warning. An `.editorconfig` entry for the rule id overrides the computed severity.
