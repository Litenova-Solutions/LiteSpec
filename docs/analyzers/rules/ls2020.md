# LS2020: Module Names a Type Outside Another Module's Contracts

A module publishes a `Contracts/` folder as its public surface and keeps everything else free to change. A read past that surface couples the caller to internals the owner may change. LS2020 reports a module that names another module's type outside its `Contracts/` folder.

## Reference

### What the Rule Enforces

LS2020 enforces [Reach Another Module Only Through Contracts](../../backend/dotnet/architecture.md#reach-another-module-only-through-contracts) (`litespec/backend/dotnet/architecture#reach-another-module-only-through-contracts`). It runs in every layer except Test. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A name reports when it resolves to a type in another module declared outside that module's `Contracts/` folder. The diagnostic sits on the name, and its message names the type and the module that owns it.

### Failing Example

```csharp
namespace Claimwick.Reporting.UseCases.ReadExpenseTotals;

internal sealed class TotalsQueryHandler
{
    public void Handle() => Expense.FromRecord();
}
```

with `Expense` declared in the spending module outside its `Contracts/` folder.

### Passing Example

```csharp
namespace Claimwick.Reporting.UseCases.ReadExpenseTotals;

internal sealed class TotalsQueryHandler(IExpenseTotals totals)
{
}
```

with `IExpenseTotals` declared in the spending module `Contracts/Ports/` folder.

### How to Fix

Read the data through a port in the owner `Contracts/Ports/` folder, which returns contract results keyed by typed identifier, or answer from data the module already holds with a query. Load no foreign aggregate or repository.

## Notes

### What the Rule Ignores

A name in a Test file, or in a file the layer rules cannot place, never reports. The rule leaves alone a type in the same module or in the owner `Contracts/` folder, and a name that resolves to no project source file. Under the `layer-projects` extension the rule does not run: project references hold the module boundary instead.
