# LS5003: Code Element Carries the Wrong Number of Marks

## Intent

LS5003 is a compiler check that reports a code element carrying more or fewer marks than its kind takes, because an extra mark answers the element to a record it does not serve. This page states what the rule reports, where the error sits, and how to carry exactly the marks the kind takes.

## Reference

### What the Rule Enforces

LS5003 enforces [Point Code and Tests up to Records](../../core/system.md#point-code-and-tests-up-to-records) (`litespec/core/system#point-code-and-tests-up-to-records`). It runs in every layer, on every marked code element and test. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

The rule reports a code element whose mark count differs from what its kind takes: a handler, event handler, job, endpoint, aggregate root, domain event, rule exception, or domain service carrying more than one mark, or an element naming one record twice, which counts as two marks. The marks table on the [model page](../../core/model.md#marks) states the count each kind takes. The diagnostic sits on the type or method name.

### Failing Example

```csharp
/// <implements>use-case/spending.submit-expense</implements>
/// <implements>use-case/spending.approve-expense</implements>
internal sealed class SubmitExpenseCommandHandler(...)
    : ICommandHandler<SubmitExpenseCommand, SubmitExpenseCommandResult>
{
    // Loads the expense, submits it, stages it, and returns the result.
}
```

### Passing Example

```csharp
/// <implements>use-case/spending.submit-expense</implements>
internal sealed class SubmitExpenseCommandHandler(...)
    : ICommandHandler<SubmitExpenseCommand, SubmitExpenseCommandResult>
{
    // Loads the expense, submits it, stages it, and returns the result.
}
```

### How to Fix

Remove the mark the kind does not take, so the element carries exactly the marks its kind takes.

## Notes

### What the Rule Ignores

The rule does not report an element with no mark; LS5001 owns that finding. It does not report an element carrying the marks its kind takes, including a method, port, adapter, or test carrying several marks. The rule stays silent when no `litespec.project.json` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error.

### Severity

Severity follows the record the finding is about: an error when it is approved or reviewed, a warning when it is a draft, and silence when it is retired. A finding covered by an open known gap or an in-date approved deviation stays silent. While `check.phase` is `frozen`, a finding on a test reports as a warning. An `.editorconfig` entry for the rule id overrides the computed severity.
