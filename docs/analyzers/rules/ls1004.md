# LS1004: State Case Is Not Sealed

An aggregate's lifecycle is a closed set: every state the business allows is already named. A state case left open for extension lets a later type add states nobody defined, so each case is either sealed or an abstract intermediate with sealed cases of its own. LS1004 reports a state case in Domain that is neither.

## Reference

### What the Rule Enforces

LS1004 enforces [Model every Aggregate lifecycle with state records](../../backend/dotnet/domain.md#model-every-aggregate-lifecycle-with-state-records) (`litespec/backend/dotnet/domain#model-every-aggregate-lifecycle-with-state-records`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md). It decides at the end of compilation, as the [Analyzers overview](../README.md) describes.

### What the Rule Reports

A non-abstract, non-sealed class deriving directly from a recognized state base reports. A state base is an abstract record whose name ends in `State` and either matches `{Aggregate}State` or is an aggregate `State` property type. The diagnostic sits on the case name.

### Failing Example

```csharp
public abstract record OrderState;

public record OrderDraftState : OrderState;
```

### Passing Example

```csharp
public abstract record OrderState;

public abstract record OrderOpenState : OrderState;

public sealed record OrderDraftState : OrderOpenState;
```

### How to Fix

Seal the case, or mark it `abstract` when it is a genuine intermediate with its own sealed cases.

## Notes

### What the Rule Ignores

A sealed case never reports, and neither does an abstract intermediate case. The rule does not run outside Domain.
