# LS1004: State Case Is Not Sealed

## Intent

LS1004 is a compiler check that reports a lifecycle state case in Domain, the project that holds business rules, left open for extension, which lets a later type add states the business never defined and stops type switches from checking every case. This page states what the rule reports, where the error sits, and how to seal the case.

## Reference

### What the Rule Enforces

LS1004 enforces [Model every Aggregate lifecycle with state records](../../backend/dotnet/domain.md#model-every-aggregate-lifecycle-with-state-records) (`litespec/backend/dotnet/domain#model-every-aggregate-lifecycle-with-state-records`). It runs in Domain only. Its category is `LiteSpec.Domain`. It reports an error and is enabled by default, as the [Analyzers overview](../README.md) describes. It decides at the end of compilation, after every type is known.

### What the Rule Reports

The rule reports a non-abstract, non-sealed class that derives directly from a recognized state base. A state base is an abstract record whose name ends in `State` and either matches `{Aggregate}State` or is an aggregate `State` property type. The diagnostic sits on the case name.

### Failing Example

```csharp
public abstract record OrderState;

public record OrderDraftState : OrderState;
```

### Passing Example

```csharp
public abstract record OrderState;

public abstract record OrderOpenState : OrderState;

public sealed record OrderDraftState : OrderOpenState;
```

### How to Fix

Mark the case `sealed`, or mark it `abstract` when it is a genuine intermediate with its own sealed cases.

## Notes

### What the Rule Ignores

The rule does not report sealed cases or abstract intermediate cases. It does not run outside Domain.
