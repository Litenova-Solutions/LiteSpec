# LS1007: Domain Event Is Not an Immutable Record

LS1007 reports a domain event that is not an immutable record. A domain event records a business fact that already happened. If callers can change the event after it was raised, the record no longer says what happened.

## Reference

### What the Rule Enforces

LS1007 enforces [Raise immutable domain facts](../../packs/dotnet/domain.md#raise-immutable-domain-facts) (`litespec/packs/dotnet/domain#raise-immutable-domain-facts`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

Any type implementing an interface named `IDomainEvent` reports unless it is a record class whose name ends in `Event`, with no settable properties and no mutable instance fields. One type gets one diagnostic even when several checks fail. The diagnostic sits on the type name.

### Failing Example

```csharp
public sealed record OrderPlacedDomainEvent : IDomainEvent
{
    public string Note { get; set; } = string.Empty;
}
```

### Passing Example

```csharp
public sealed record OrderPlacedDomainEvent(OrderId OrderId) : IDomainEvent;
```

### How to Fix

Declare the event as a record class named `{Aggregate}{PastFact}DomainEvent` that implements `IDomainEvent`, carries business data only, and exposes its members through `init` setters or readonly fields.

## Notes

### What the Rule Ignores

Interfaces that merely extend `IDomainEvent` never report. Event records with only `init` setters, `readonly` fields, `static` fields, or constants pass. The kind suffix is out of scope: [LS2031](ls2031.md) reports a domain event whose name does not end in `DomainEvent`. The rule does not run outside Domain.
