# LS5007: Marked Act Raises an Undeclared Event

A use case lists in `raises` every event its act may raise, so reviewers see each consequence. An event raised but never listed starts a consequence nobody reviewed. LS5007 reports an aggregate method marked with a use case that raises an event the use case does not list.

## Reference

### What the Rule Enforces

LS5007 enforces [Raise the Declared Events from the Marked Act](../../backend/domain.md#raise-the-declared-events-from-the-marked-act) (`litespec/backend/domain#raise-the-declared-events-from-the-marked-act`). It runs in Domain only. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

A root method marked with a use case reports when it raises an event the use case does not list in `raises`. `use-case/spending.approve-expense` lists `domain-event/expense.approved` in `raises` and nothing else. The diagnostic sits on the method name.

### Failing Example

```csharp
/// <implements>use-case/spending.approve-expense</implements>
public void Approve(ApproverId approver, DateTimeOffset decidedAt)
{
    State = new ExpenseApprovedState(approver, decidedAt);
    RaiseDomainEvent(new ExpenseApprovedEvent(Id));
    RaiseDomainEvent(new ExpenseReimbursedEvent(Id));
}
```

### Passing Example

```csharp
/// <implements>use-case/spending.approve-expense</implements>
public void Approve(ApproverId approver, DateTimeOffset decidedAt)
{
    State = new ExpenseApprovedState(approver, decidedAt);
    RaiseDomainEvent(new ExpenseApprovedEvent(Id));
}
```

### How to Fix

Add the event to the use case `raises`, or stop raising it from the marked method.

## Notes

### What the Rule Ignores

A method with no use-case mark never reports, and neither does an event the use case lists in `raises`. The rule stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error. It does not run outside Domain.

### Severity

The rule reports an error. A finding that a live waiver covers stays silent, and an `.editorconfig` entry for the rule id overrides the computed severity.
