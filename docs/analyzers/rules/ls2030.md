# LS2030: Contracts Project Declares an Interface

LS2030 reports an interface declared in a Contracts project. A Contracts project publishes data only, grouped by aggregate: identifiers, facts, and public queries and public commands with their results. A consumer sends another module's public queries and public commands from its own handler, reaction, or job, so an interface in the provider's contracts describes a call nobody may make.

## Reference

### What the Rule Enforces

LS2030 enforces [Publish Only Data from Each Contracts Project](../../packs/dotnet/architecture.md#publish-only-data-from-each-contracts-project) (`litespec/packs/dotnet/architecture#publish-only-data-from-each-contracts-project`). It runs in every layer except Test. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

An interface reports when a Contracts file declares it: a file under a nested `Contracts/` folder or in a sibling `{Product}.{Module}.Contracts` project. The diagnostic sits on the interface name, and its message names the interface.

### Failing Example

```csharp
namespace Claimwick.Books.Contracts.Books;

internal interface IBookReader
{
}
```

The interface sits in the books module Contracts, where only data may live.

### Passing Example

```csharp
namespace Claimwick.Books.Contracts.Books.OnBookLent;

internal sealed record BookLentModuleEvent(System.Guid Book);
```

The fact is data, so it belongs in Contracts.

### How to Fix

Delete the interface from Contracts. Send the provider's public query or public command from the consumer's own handler, reaction, or job instead.

## Notes

### What the Rule Ignores

An interface in a module `Ports/` folder, a record, class, struct, or enum in a Contracts project, and a type in a Test file never report. A nested interface inside a Contracts type reports like a top-level one.
