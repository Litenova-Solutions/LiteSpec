# LS2017: LiteSpecLayer Names No Known Layer

LS2017 reports a `LiteSpecLayer` value that names no known layer. Under the `layer-projects` extension, a project says which layer it holds through that property, and a misspelled value would silently turn the analyzers off for that project.

## Reference

### What the Rule Enforces

LS2017 enforces [Package Each Layer as Its Own Project](../../backend/dotnet/ext/layer-projects.md#package-each-layer-as-its-own-project) (`litespec/backend/dotnet/ext/layer-projects#package-each-layer-as-its-own-project`). It runs in every project that declares `LiteSpecLayer`, whatever the value. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A declared `LiteSpecLayer` value reports when it names no known layer: anything but `Domain`, `Application.Abstractions`, `Application`, `Infrastructure`, `WebApi`, `Worker`, `Test`, `Tests`, or `None`, ignoring dots and case. The diagnostic sits on the first token of the first file, and its message names the declared value and the accepted names.

### Failing Example

```csharp
namespace Shop.Billing;

internal sealed class ChargeDuesJob
{
}
```

with `<LiteSpecLayer>Staging</LiteSpecLayer>` in the project file.

### Passing Example

```csharp
namespace Shop.Billing;

internal sealed class ChargeDuesJob
{
}
```

with `<LiteSpecLayer>Worker</LiteSpecLayer>` in the project file.

### How to Fix

Point `LiteSpecLayer` at the layer the project holds, or set it to `None` to opt the project out. Under the default module layout the analyzers read each file's layer from its folder, so `LiteSpecLayer` has no effect there.

## Notes

### What the Rule Ignores

A project declaring no `LiteSpecLayer` value never reports: without the property, the analyzers read the assembly name suffix under `layer-projects`. The `None` value, which opts the project out on purpose, never reports either.
