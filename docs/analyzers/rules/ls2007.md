# LS2007: Reaction or Job Name Hides Its Kind

LS2007 reports a reaction or job whose name hides its kind. A reaction answers a domain event and a job runs scheduled work. Each name says which trigger it answers, so the model builder can discover it by name.

## Reference

### What the Rule Enforces

LS2007 enforces [Use architectural suffixes](../../workspace/naming.md#use-architectural-suffixes) (`litespec/workspace/naming#use-architectural-suffixes`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a class implementing an interface named `IEventHandler` or `IDomainEventReaction` unless its name matches `{Action}On{Fact}Handler`, with an action before `On` and a fact between `On` and `Handler`. It reports a class deriving from `BackgroundService` unless its name ends in `Job` or `Worker`, or contains `Recurring`. The diagnostic sits on the type name, and its message names the kind and the accepted shape.

### Failing Example

```csharp
internal sealed class SubscriberNotifier : IEventHandler<LoanBorrowedEvent>
{
}

internal sealed class LoanBorrowedNotifier : IDomainEventReaction
{
}


internal sealed class ReminderLoop : BackgroundService
{
}
```

### Passing Example

```csharp
internal sealed class SendDueNoticeOnLoanBorrowedHandler : IEventHandler<LoanBorrowedEvent>
{
}

internal sealed class ReminderJob : BackgroundService
{
}
```

### How to Fix

Name a reaction `{Action}On{Fact}Handler`. End a job name in `Job` or `Worker`, or include `Recurring` in it.

File a reaction in the `Application/` folder of the use case it runs, such as `Spending/UseCases/ApproveExpense/Application/`, not in a `UseCases/On{Fact}/` folder. A job that runs a use case sits there too. A job that only sends a notification or calls an external system sits in the module's `Notifications/` or `ExternalSystems/` folder instead. This rule checks the name; the model's placement check checks the folder.

## Notes

### What the Rule Ignores

A read-model projection never reports: one named `{ReadModel}On{Fact}Projection` or filed in a module `ReadModels/` folder rebuilds a read-model row and carries the read model's name instead. A class that is neither a reaction nor a job is out of scope, as are interfaces. A class implementing bare `IHostedService` without deriving `BackgroundService` is host wiring, not a job. A class that is both a reaction and a job is checked against both shapes. The rule does not run in Domain or WebApi.
