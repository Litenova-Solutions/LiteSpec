# LS1014: Aggregate Part Constructed Outside Its Domain Folder

LS1014 reports a file outside an aggregate's `Domain/` folder that constructs a type from that folder. The aggregate root is the only entry point to its aggregate: callers pass plain inputs to the root's named factories and methods, and the root alone builds its entities and value objects.

## Reference

### What the Rule Enforces

LS1014 enforces [Construct Aggregate Parts Only Inside the Root](../../backend/dotnet/domain.md#construct-aggregate-parts-only-inside-the-root) (`litespec/backend/dotnet/domain#construct-aggregate-parts-only-inside-the-root`). It runs in every production layer, wherever the construction sits. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A `new` expression reports when it constructs a type declared in an aggregate's `Domain/` folder from a file outside that folder. The aggregate folder is `Domain/{Aggregates}/` under one project per module, or `{Module}/Domain/{Aggregates}/` under one modules project. The diagnostic sits on the constructed type name, and its message names the type and the aggregate it belongs to.

### Failing Example

```csharp
namespace Claimwick.Spending.Application.PostManualEntry;

internal sealed class PostManualEntryCommandHandler
{
    public Expense Post(ExpenseFacts facts)
    {
        var lines = new ExpenseLine(facts.Lines);
        return Expense.Post(lines, facts.Business);
    }
}
```

with the file in `Spending/Application/PostManualEntry/` and `ExpenseLine` declared in `Spending/Domain/Expenses/`. The handler builds the aggregate's part instead of letting the root build it.

### Passing Example

```csharp
namespace Claimwick.Spending.Application.PostManualEntry;

internal sealed class PostManualEntryCommandHandler
{
    public Expense Post(ExpenseFacts facts)
    {
        return Expense.PostManual(facts, facts.Business);
    }
}
```

The handler calls the root with plain inputs, and the root builds its lines inside its own method.

### How to Fix

Move the construction into the root: add a named factory or method on the root that takes the plain inputs and builds the parts. Keep input records the root takes as parameters beside the caller or in the aggregate folder; the rule leaves the root's input types alone.

## Notes

### What the Rule Ignores

Construction inside the aggregate's own `Domain/` folder never reports: the root builds its parts there. The rule leaves alone the root's input records and typed identifiers: a type the root takes as a parameter, a type whose name ends in `Id`, or a type implementing `IStronglyTypedId`. The root itself reports when a file outside its folder constructs it: callers reach the root through its named factories, never through `new`. A `new` expression in a Test file, or in a file the layer rules cannot place, never reports. Construction of a type with no project source file, of a type outside every aggregate folder, or of a type directly under a module `Domain/` folder never reports.
