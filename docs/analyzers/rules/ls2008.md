# LS2008: Event Handler Sits Outside Its Fact Folder

## Intent

LS2008 is a compiler check that reports an event handler, the type that answers a domain event, declared outside the folder named for the fact it handles, so the handlers of one fact no longer list together. This page states what the rule reports, where the error sits, and how to file the handler with its fact.

## Reference

### What the Rule Enforces

LS2008 enforces [Group event handlers by the fact they handle](../../workspace/naming.md#group-event-handlers-by-the-fact-they-handle) (`litespec/workspace/naming#group-event-handlers-by-the-fact-they-handle`). It runs in Application and Infrastructure. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a class that implements a generic interface named `IEventHandler` for one event type, unless its namespace ends in `.On{Fact}`, where `{Fact}` is the event type name without its `Event` suffix. The diagnostic sits on the type name, and its message names the handler, the event, and the expected folder.

### Failing Example

```csharp
namespace Shop.Loans;

internal sealed class SendDueNoticeOnLoanBorrowedHandler : IEventHandler<LoanBorrowedEvent>
{
}
```

### Passing Example

```csharp
namespace Shop.Loans.OnLoanBorrowed;

internal sealed class SendDueNoticeOnLoanBorrowedHandler : IEventHandler<LoanBorrowedEvent>
{
}
```

### How to Fix

Move the handler into the `On{Fact}` folder inside its subscriber's aggregate folder, so its namespace ends in `.On{Fact}`.

## Notes

### What the Rule Ignores

The rule does not report a handler of two facts or a class that implements no generic `IEventHandler`. It does not run in Domain, Application.Abstractions, or WebApi.
