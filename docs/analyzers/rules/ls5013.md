# LS5013: Base Declares a Non-Virtual Code

LS5013 reports a marked rule exception whose base declares a non-virtual `Code`. The generator writes the refusal code as an override in the partial exception; against a non-virtual base it would emit hiding code, so it reports instead and writes no part.

## Reference

### What the Rule Enforces

LS5013 enforces [Define the Shared Domain Contracts Once](../../packs/dotnet/domain.md#define-the-shared-domain-contracts-once) (`litespec/packs/dotnet/domain#define-the-shared-domain-contracts-once`). It runs where the generator writes exception parts. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

A marked, partial rule exception without a hand-written `Code` reports when the nearest base declaring `Code` declares it non-virtual: a plain property, a field, or any member the generated part cannot override. The generator writes no part for the exception until the base is fixed. The diagnostic has no source location, because the generator reads the marked type without keeping its syntax. Its message names the exception and the base that declares the member.

### Failing Example

```csharp
public abstract class DomainException : Exception
{
    protected DomainException(string code, string message)
        : base(message)
    {
        Code = code;
    }

    public string Code { get; }
}
```

Every partial exception under this base reports LS5013, and the generator writes no `Code` part for any of them.

### Passing Example

```csharp
public abstract class DomainException : Exception
{
    protected DomainException(string message)
        : base(message)
    {
    }

    public abstract string Code { get; }
}
```

The generator writes `public override string Code => "...";` into each partial exception from its rule's refusal code.

### How to Fix

Declare the base member `public abstract string Code { get; }` and take only the message in the constructor. A base that declares no `Code` at all keeps the plain generated property.

## Notes

### What the Rule Ignores

The rule stays silent when the exception declares its own `Code`, when it is not partial, when its rule record is unknown, and when the base declares an abstract or virtual `Code` or none at all. It does not run in test projects, where no exception parts are generated. It stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error.

### Severity

The rule is an error whenever it fires, because no code can be generated for the exception until the base is fixed. An `.editorconfig` entry for the rule id overrides it.
