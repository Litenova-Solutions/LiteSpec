# LS1011: Public Domain Contract Is Undocumented

Every public type and member in Domain stands for a business constraint, result, or failure, and readers rely on its XML documentation to learn which. An undocumented contract leaves them guessing. LS1011 reports the contract with no documentation.

## Reference

### What the Rule Enforces

LS1011 enforces [Document every public Domain contract](../../backend/dotnet/domain.md#document-every-public-domain-contract) (`litespec/backend/dotnet/domain#document-every-public-domain-contract`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A public type or member without XML documentation reports. The rule checks classes, structs, interfaces, records, enums, delegates, ordinary methods, constructors, properties, events, and fields. A non-empty `<summary>` element or an `<inheritdoc/>` element satisfies it, including `///` lines in a build without a documentation file. The diagnostic sits on the identifier.

### Failing Example

```csharp
/// <summary>An order placed by a customer.</summary>
public sealed class Order
{
    public void Cancel()
    {
    }
}
```

### Passing Example

```csharp
/// <summary>An order placed by a customer.</summary>
public sealed class Order
{
    /// <summary>Cancels the order before it ships.</summary>
    public void Cancel()
    {
    }
}
```

### How to Fix

Write a `<summary>` line stating the business constraint, result, or failure the member represents, or an `<inheritdoc/>` line when the contract inherits its documentation.

## Notes

### What the Rule Ignores

Internal, private, and nested non-public contracts never report, and neither do overrides or explicit interface implementations. Protected members of public types still need documentation. The rule does not run outside Domain.
