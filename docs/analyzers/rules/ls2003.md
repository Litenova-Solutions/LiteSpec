# LS2003: WebApi Uses an MVC Controller

The .NET stack gives each HTTP operation its own endpoint class, so every route reads and reviews on its own. A controller groups several operations behind shared filters and routing, which hides what each route does. LS2003 reports an MVC controller class in the WebApi project.

## Reference

### What the Rule Enforces

LS2003 enforces [Exclude MVC controllers from the stack](../../backend/dotnet/api.md#exclude-mvc-controllers-from-the-stack) (`litespec/backend/dotnet/api#exclude-mvc-controllers-from-the-stack`). It runs in WebApi only. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A class reports when it derives from `ControllerBase` or `Controller`, directly or through an intermediate base, or carries the `ApiController` attribute. A class that does both gets one diagnostic. The diagnostic sits on the class name.

### Failing Example

```csharp
public sealed class OrdersController : ControllerBase { }
```

### Passing Example

```csharp
internal sealed class GetOrderEndpoint : IEndpoint
{
    public void Map() { }
}
```

### How to Fix

Replace the controller with one `IEndpoint` per operation.

## Notes

### What the Rule Ignores

An endpoint class never reports. The rule does not run outside WebApi.
