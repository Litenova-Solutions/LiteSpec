# LS2029: File Names a Contract Type Outside Its Layer

LS2029 reports a module file that names another module's public query, public command or result from a type its role may not name, and a Platform file that names a module identifier. A handler asks another module one question through the query mediator, and a reaction or a job sends the follow-on command, so a query or command named anywhere else couples the caller to a call nobody declared. The Platform speaks the tenant and the actor, never a business identifier the modules own.

## Reference

### What the Rule Enforces

LS2029 enforces [Follow Layer Direction in Every File](../../packs/dotnet/architecture.md#follow-layer-direction-in-every-file) (`litespec/packs/dotnet/architecture#follow-layer-direction-in-every-file`). It runs in every layer except Test, including Platform files. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A reference in a module file reports when it resolves to a public query, public command, or result of another module that the referencing type cannot use: a type in a `{UseCase}/` folder below an aggregate folder of that module's Contracts project, or a module-level public query or public command in its own Contracts folder. A type in an `On{Fact}/` folder below an aggregate folder is a fact, never a public query, public command, or result.

A handler, a reaction, or a job can reference a public query or query result; only a reaction or a job can reference a public command or command result. A name carrying `Command` is command-side; every other query or result name is query-side. Referencing another module's identifiers and facts from any file stays allowed.

A reference in a Platform file reports when it resolves to a module identifier: a type ending in `Id` declared in a module. The diagnostic sits on the reference, and its message states the file's layer, the type, and why the layer cannot use it: for a query or command, the provider module and which roles can use it; for an identifier, that the Platform lists no business identifier.

### Failing Example

```csharp
namespace Claimwick.Reading.Application.BorrowBook;

internal sealed class BorrowBookCommandHandler
{
    internal void Handle(LendBookCommand command)
    {
    }
}
```

with `LendBookCommand` declared in the books module `Contracts/Books/LendBook/` folder. A handler sends no command, so it names none.

An adapter naming another module's public query reports the same way:

```csharp
namespace Claimwick.Reading.Infrastructure.Borrowing;

internal sealed class BorrowingAdapter
{
    internal ReadBookQuery Query() => new();
}
```

with `ReadBookQuery` declared in the books module `Contracts/Books/ReadBook/` folder. An adapter implements its own port, so it lists no other module's query or command.

A Platform file reports the same way:

```csharp
namespace Claimwick.Platform.Access;

internal sealed class ActorScope
{
    internal void Attach(BookId book)
    {
    }
}
```

with `BookId` declared in the books module Contracts.

### Passing Example

```csharp
namespace Claimwick.Reading.Application.BorrowBook;

internal sealed class BorrowBookQueryHandler
{
    internal void Handle(ReadBookQuery query)
    {
    }
}
```

with `ReadBookQuery` declared in the books module `Contracts/Books/ReadBook/` folder. The handler sends the query through the query mediator, so it names the query and its result.

A reaction naming another module's public command passes the same way:

```csharp
namespace Claimwick.Reading.Application.BorrowBook;

internal sealed class LendBookOnBookReservedHandler : IEventHandler<BookReservedEvent>
{
    internal void Handle(LendBookCommand command)
    {
    }
}
```

with `LendBookCommand` declared in the books module `Contracts/Books/LendBook/` folder. The reaction sends the command, so it names it.

### How to Fix

Send another module's public query from a handler, reaction, or job through the query mediator, and its public command from a reaction or a job through the command mediator, with the record declaring the edge. Move a business identifier the Platform reads into the module that owns it, and convert at the module edge: the Platform speaks the tenant and the actor.

## Notes

### What the Rule Ignores

A name in a Test file never reports. The rule leaves alone a name resolving to the file's own module, a module identifier or fact named from a module file, a public query or query result named from a handler, reaction, or job, a public command or command result named from a reaction or a job, a Kernel value or the Platform's own type named from a Platform file, and a name that resolves to no project source file. A file outside every module, such as a host file, never reports. A name outside every type reports.
