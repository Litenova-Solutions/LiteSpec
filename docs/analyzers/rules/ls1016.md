# LS1016: Aggregate References Another Aggregate by Object

LS1016 reports a property of one aggregate typed as another aggregate's root or entity. An aggregate references another aggregate by its typed identifier only: an object reference couples two consistency boundaries and their storage.

## Reference

### What the Rule Enforces

LS1016 enforces [Reference Other Aggregates by Typed Identifier](../../packs/dotnet/domain.md#reference-other-aggregates-by-typed-identifier) (`litespec/packs/dotnet/domain#reference-other-aggregates-by-typed-identifier`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A property declared in an aggregate's `Domain/` folder reports when its type, after unwrapping nullable, array, and generic wrappers, is the root or a child entity of another aggregate. A root is a class deriving from `AggregateRoot` with one type argument, and a child entity is a class deriving from `Entity` with one type argument, in any namespace. The diagnostic sits on the property, and its message names the property, the referenced type, and its aggregate.

### Failing Example

```csharp
namespace Claimwick.Spending.Domain.Expense;

public sealed class Expense : AggregateRoot<ExpenseId>
{
    public Counterparty Counterparty { get; }
}
```

with `Counterparty` the root of the counterparty aggregate. The expense holds the counterparty object instead of its identifier.

### Passing Example

```csharp
namespace Claimwick.Spending.Domain.Expense;

public sealed class Expense : AggregateRoot<ExpenseId>
{
    public CounterpartyId CounterpartyId { get; }
}
```

The expense stores the typed identifier, and Application loads the counterparty through its own repository when a command needs both.

### How to Fix

Replace the object reference with the typed identifier of the other aggregate. A command that coordinates both aggregates loads each side through its own domain repository.

## Notes

### What the Rule Ignores

A property typed as its own aggregate's root or entities never reports, and neither does an indexer. A property directly under a module `Domain/` folder, outside every aggregate folder, or outside Domain never reports. A type with no project source file cannot be placed in an aggregate, so a property typed as one never reports.
