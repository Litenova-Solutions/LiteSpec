# LS5008: Declared Event Is Raised by No Marked Act

LS5008 reports a listed event that no marked method raises. A use case lists in `raises` every event its act raises, and the code keeps that promise by raising each listed event from a method marked with the use case; a listed event no marked method raises is a promise the code does not keep.

## Reference

### What the Rule Enforces

LS5008 enforces [Raise the Declared Events from the Marked Act](../../backend/domain.md#raise-the-declared-events-from-the-marked-act) (`litespec/backend/domain#raise-the-declared-events-from-the-marked-act`). It runs in Domain only. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

A use case listing an event in `raises` reports when no root method marked with the use case raises it. `use-case/spending.submit-expense` lists `domain-event/expense.submitted` in `raises`. The diagnostic sits on each root method marked with the use case.

### Failing Example

```csharp
/// <implements>use-case/spending.submit-expense</implements>
public void Submit()
{
    State = new ExpenseSubmittedState();
}
```

### Passing Example

```csharp
/// <implements>use-case/spending.submit-expense</implements>
public void Submit()
{
    State = new ExpenseSubmittedState();
    RaiseDomainEvent(new ExpenseSubmittedEvent(Id));
}
```

### How to Fix

Raise the listed event from a method marked with the use case, or drop it from `raises`.

## Notes

### What the Rule Ignores

A use case listing no event in `raises` never reports. Neither does a use case whose every listed event a marked method raises.

The rule stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error. It does not run outside Domain.

### Severity

The rule reports an error. A finding that a live waiver covers stays silent, and an `.editorconfig` entry for the rule id overrides the computed severity.
