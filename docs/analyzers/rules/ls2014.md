# LS2014: Command Handler Finds or Creates

## Intent

LS2014 is a compiler check that reports a command handler, the type that runs the state change, that both finds a record and creates it in one method, hiding two use cases behind one name. This page states what the rule reports, where the error sits, and how to split the flow across the boundary that owns it.

## Reference

### What the Rule Enforces

LS2014 enforces [Implement one outcome path per command](../../backend/application.md#implement-one-outcome-path-per-command) (`litespec/backend/application#implement-one-outcome-path-per-command`). It runs in Application and Infrastructure. Its category is `LiteSpec.Layers`. It reports an error and is enabled by default, as the [Analyzers overview](../README.md) describes.

### What the Rule Reports

The rule reports a command handler, which is a class whose name ends in `CommandHandler` or that implements `ICommandHandler`, with one method that calls a repository method whose name starts in `Find` and also calls a static method or constructor that returns the found type, ignoring `Task` and nullability. For a constructor the diagnostic sits on the created type; for a static factory it sits on the invoked member name. Its message names the handler and the created type.

### Failing Example

```csharp
internal sealed class RegisterReaderCommandHandler(IReaderRepository readerRepository)
{
    public void Handle(RegisterReaderCommand command)
    {
        var existing = readerRepository.FindByCard(command.CardId);
        var reader = Reader.Register(command.CardId);
    }
}
```

### Passing Example

```csharp
internal sealed class RegisterReaderCommandHandler(IReaderRepository readerRepository)
{
    public void Handle(RegisterReaderCommand command)
    {
        var reader = Reader.Register(command.CardId);
        readerRepository.Store(reader);
    }
}
```

### How to Fix

Split the flow into two use cases: the boundary that owns the flow runs a query first, then sends the command that fits. When the create loses a race, it refuses with its conflict, and the owner sends the other command.

## Notes

### What the Rule Ignores

The rule does not report a handler that only finds, a handler that only creates, a creation of another type than the found one, or a find and a creation in different methods. It does not report query handlers. It does not run in Domain, Application.Abstractions, or WebApi.
