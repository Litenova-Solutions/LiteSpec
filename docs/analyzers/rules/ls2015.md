# LS2015: Command Handler Changes Records in a Loop

A command runs in one unit of work, so a handler that changes records in a loop rolls back the whole batch when one record fails, and holds locks for the batch's whole length. Per-record work belongs to a job that runs one command per record instead. LS2015 reports a handler that writes inside a loop.

## Reference

### What the Rule Enforces

LS2015 enforces [Issue per-record work from a job](../../backend/application.md#issue-per-record-work-from-a-job) (`litespec/backend/application#issue-per-record-work-from-a-job`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A command handler, which is a class whose name ends in `CommandHandler` or that implements `ICommandHandler`, reports when a `for`, `foreach`, or `while` body in it calls a repository `Store`, `Add`, `Update`, or `Delete` method. The diagnostic sits on the invoked member name, and its message names the handler and the call.

### Failing Example

```csharp
internal sealed class ExpireLoansCommandHandler(ILoanRepository loanRepository)
{
    public void Handle(ExpireLoansCommand command, List<Loan> loans)
    {
        foreach (var loan in loans)
        {
            loan.Expire(command.Now);
            loanRepository.Store(loan);
        }
    }
}
```

### Passing Example

```csharp
internal sealed class ExpireLoanCommandHandler(ILoanRepository loanRepository)
{
    public void Handle(ExpireLoanCommand command, Loan loan)
    {
        loan.Expire(command.Now);
        loanRepository.Store(loan);
    }
}
```

### How to Fix

Move the work to a job that sends one command per record, each in its own unit of work, resuming from its cursor after a failure.

## Notes

### What the Rule Ignores

A loop that only builds a result list never reports, and neither does a write immediately followed by a return or throw in the same block, a loop calling `Store`, `Add`, `Update`, or `Delete` on a type that is not a repository, or a write outside a loop. Loops in a query handler or an event handler are out of scope. The rule does not run in Domain or WebApi.
