# LS2015: Command Handler Changes Records in a Loop

LS2015 reports a command handler that changes records inside a loop. A command runs in one unit of work, so such a handler rolls back the whole batch when one record fails and holds locks for the batch's whole length; per-record work belongs to a job that runs one command per record instead.

## Reference

### What the Rule Enforces

LS2015 enforces [Issue per-record work from a job](../../backend/application.md#issue-per-record-work-from-a-job) (`litespec/backend/application#issue-per-record-work-from-a-job`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A command handler is a class whose name ends in `CommandHandler` or that implements `ICommandHandler`. It reports when a `for`, `foreach`, or `while` body in it calls a repository `Store`, `Add`, `Update`, or `Delete` method. The diagnostic sits on the invoked member name, and its message names the handler and the call.

### Failing Example

```csharp
internal sealed class ExpireLoansCommandHandler
{
    private readonly ILoanRepository _loanRepository;

    public ExpireLoansCommandHandler(ILoanRepository loanRepository)
    {
        _loanRepository = loanRepository;
    }

    public void Handle(ExpireLoansCommand command, List<Loan> loans)
    {
        foreach (var loan in loans)
        {
            loan.Expire(command.Now);
            _loanRepository.Store(loan);
        }
    }
}
```

### Passing Example

```csharp
internal sealed class ExpireLoanCommandHandler
{
    private readonly ILoanRepository _loanRepository;

    public ExpireLoanCommandHandler(ILoanRepository loanRepository)
    {
        _loanRepository = loanRepository;
    }

    public void Handle(ExpireLoanCommand command, Loan loan)
    {
        loan.Expire(command.Now);
        _loanRepository.Store(loan);
    }
}
```

### How to Fix

Move the work to a job that sends one command per record, each in its own unit of work, resuming from its cursor after a failure.

## Notes

### What the Rule Ignores

A loop that only builds a result list never reports. Neither does a write immediately followed by a return or throw in the same block, a loop calling `Store`, `Add`, `Update`, or `Delete` on a type that is not a repository, or a write outside a loop. A command handler whose use case record states `consistency` with `mode: per-record` never reports: each instance it stages is independent, so the loop stages several instances in one commit. Loops in a query handler or an event handler are out of scope. The rule does not run in Domain or WebApi.
