# LS2012: Handler Authorizes Itself

Authorization belongs to the pipeline guard, which runs before the handler and decides from the declared grant. A command or query handler that throws an access refusal, or takes the authorization guard to decide for itself, puts that check in the wrong place. LS2012 reports either case.

## Reference

### What the Rule Enforces

LS2012 enforces [Enforce target authorization in the pipeline](../../backend/application.md#enforce-target-authorization-in-the-pipeline) (`litespec/backend/application#enforce-target-authorization-in-the-pipeline`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a command or query handler, which is a class whose name ends in `CommandHandler` or `QueryHandler`, or that implements `ICommandHandler` or `IQueryHandler`, in either of two cases. The first case is a handler throwing an exception type whose name ends in `ForbiddenException`, `UnauthorizedException`, or `AccessDeniedException`. For a `throw new` the diagnostic sits on the created exception type; for any other thrown value it sits on that value. The second case is a handler taking a constructor parameter typed as the authorization guard: a type whose name ends in `AuthorizationGuard`, or a type that derives from or implements such a type. The diagnostic sits on the parameter type. In either case its message names the handler and the exception or guard type.

### Failing Example

```csharp
internal sealed class RenewLoanCommandHandler
{
    public void Handle(RenewLoanCommand command)
    {
        throw new LoanForbiddenException();
    }
}
```

```csharp
internal sealed class RenewLoanCommandHandler(IAuthorizationGuard authorizationGuard)
{
}
```

### Passing Example

```csharp
internal sealed class RenewLoanCommandHandler(ILoanRepository loanRepository)
{
    public void Handle(RenewLoanCommand command)
    {
        var loan = loanRepository.GetById(command.LoanId);
        loanRepository.Store(loan);
    }
}
```

### How to Fix

Put the grant on the use-case record and let the authorization guard enforce it before the handler runs, so the handler never compares the caller with a target, never throws the forbidden refusal itself, and never takes the authorization guard. Remove the guard parameter from the handler constructor and leave the guard in the pipeline.

## Notes

### What the Rule Ignores

A throw of any other exception type never reports, and neither does a throw in an event handler or a job, or a rethrow without a value. The authorization guard taken outside a constructor, or taken by a type that is not a command or query handler, is out of scope, as is a handler taking any other constructor type, such as a repository. The rule does not run in Domain or WebApi.
