# LS2012: Handler Authorizes Itself

LS2012 reports a command or query handler that authorizes its own target. Authorization belongs to the pipeline guard, which runs before the handler and decides from the declared grant; a handler that throws an access refusal, or takes the guard to decide for itself, puts that check in the wrong place.

## Reference

### What the Rule Enforces

LS2012 enforces [Enforce target authorization in the pipeline](../../core/backend-application.md#enforce-target-authorization-in-the-pipeline) (`litespec/core/backend-application#enforce-target-authorization-in-the-pipeline`). It runs in Application, Infrastructure, and Worker. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A command or query handler is a class whose name ends in `CommandHandler` or `QueryHandler`, or that implements `ICommandHandler` or `IQueryHandler`. The rule reports such a handler in either of two cases.

First, the handler throws an access refusal: an exception type whose name ends in `ForbiddenException`, `UnauthorizedException`, or `AccessDeniedException`. For a `throw new` the diagnostic sits on the created exception type; for any other thrown value it sits on that value.

Second, the handler takes the authorization guard as a constructor parameter: a type whose name ends in `AuthorizationGuard`, or a type that derives from or implements such a type. The diagnostic sits on the parameter type. In either case the message names the handler and the exception or guard type.

### Failing Example

```csharp
internal sealed class RenewLoanCommandHandler
{
    public void Handle(RenewLoanCommand command)
    {
        throw new LoanForbiddenException();
    }
}
```

```csharp
internal sealed class RenewLoanCommandHandler
{
    private readonly IAuthorizationGuard _authorizationGuard;

    public RenewLoanCommandHandler(IAuthorizationGuard authorizationGuard)
    {
        _authorizationGuard = authorizationGuard;
    }
}
```

### Passing Example

```csharp
internal sealed class RenewLoanCommandHandler
{
    private readonly ILoanRepository _loanRepository;

    public RenewLoanCommandHandler(ILoanRepository loanRepository)
    {
        _loanRepository = loanRepository;
    }

    public void Handle(RenewLoanCommand command)
    {
        var loan = _loanRepository.GetById(command.LoanId);
        _loanRepository.Store(loan);
    }
}
```

### How to Fix

Declare the grant on the use-case record and let the authorization guard enforce it before the handler runs. The handler then never compares the caller with a target, never throws the forbidden refusal itself, and never takes the authorization guard: remove the guard parameter from the handler constructor and leave the guard in the pipeline.

## Notes

### What the Rule Ignores

A throw of any other exception type never reports. Neither does a throw in an event handler or a job, or a rethrow without a value. A guard taken outside a constructor, or taken by a type that is not a command or query handler, is out of scope, as is a handler taking any other constructor type, such as a repository. The rule does not run in Domain or WebApi.
