# LS5006: Marked Event or Exception Is Not Partial

LS5006 reports a marked domain event or rule exception that is not declared as a `partial` type. The generator writes each event `Classification` and exception `Code` as a second part of its type, and it can only add that part to a type declared `partial`.

## Reference

### What the Rule Enforces

LS5006 enforces [Declare Marked Events and Exceptions as Partial Types](../../backend/dotnet/stack.md#declare-marked-events-and-exceptions-as-partial-types) (`litespec/backend/dotnet/stack#declare-marked-events-and-exceptions-as-partial-types`). It runs in Domain only. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

A domain event or a rule exception carrying a mark reports when it is not declared `partial`, in a project where the analyzer package generates values. The diagnostic sits on the type name.

### Failing Example

```csharp
/// <implements>domain-event/expense.submitted</implements>
public sealed record ExpenseSubmittedEvent(ExpenseId ExpenseId, Money Amount) : IDomainEvent;
```

### Passing Example

```csharp
/// <implements>domain-event/expense.submitted</implements>
public sealed partial record ExpenseSubmittedEvent(ExpenseId ExpenseId, Money Amount) : IDomainEvent;
```

### How to Fix

Add `partial` to the type declaration, so the generator can add the runtime value as a second part. A code fix adds `partial`, with Fix All. A second code fix deletes a hand-written value that equals the record, with Fix All.

## Notes

### What the Rule Ignores

An event or exception with no mark never reports, and neither does a type that is already `partial`.

The rule stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error. It does not run outside Domain.

### Severity

The rule reports an error. A finding that a live waiver covers stays silent, and an `.editorconfig` entry for the rule id overrides the computed severity.
