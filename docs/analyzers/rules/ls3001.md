# LS3001: Asynchronous Method Name Lacks Async

## Intent

LS3001 is a compiler check that reports an async method whose name does not end in Async, which reads as a plain call where it is used, so readers miss the await and the cancellation token it needs. This page states what the rule reports, where the error sits, and how to complete the name.

## Reference

### What the Rule Enforces

LS3001 enforces [Name asynchronous methods completely](../../backend/dotnet/naming.md#name-asynchronous-methods-completely) (`litespec/backend/dotnet/naming#name-asynchronous-methods-completely`). It runs in all five projects. Its category is `LiteSpec.Style`. It reports an error and is enabled by default, as the [Analyzers overview](../README.md) describes.

### What the Rule Reports

The rule reports a method or local function that returns `Task` or `ValueTask`, including the generic forms, whose name does not end in `Async`. The diagnostic sits on the method name. Its message names the return type.

### Failing Example

```csharp
public Task Place() => Task.CompletedTask;
```

### Passing Example

```csharp
public Task PlaceAsync(CancellationToken cancellationToken) => Task.CompletedTask;
```

### How to Fix

End the method name in `Async`.

## Notes

### What the Rule Ignores

The rule does not report overrides, explicit interface implementations, implementations of members from outside interfaces such as framework contracts, the static `Main` entry point, or lambdas. It does not run outside the five projects.
