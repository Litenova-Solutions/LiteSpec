# LS3001: Asynchronous Method Name Lacks Async

Readers recognize an async method by its `Async` suffix. Without it, the call reads as plain and synchronous where it is used, hiding the await and the cancellation token it needs. LS3001 reports the incomplete name.

## Reference

### What the Rule Enforces

LS3001 enforces [Name asynchronous operations completely](../../workspace/naming.md#reveal-asynchrony-and-cancellation-in-operation-names) (`litespec/workspace/naming#reveal-asynchrony-and-cancellation-in-operation-names`). It runs in every production project. Its category is `LiteSpec.Style`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A method or local function returning `Task` or `ValueTask`, including the generic forms, reports when its name does not end in `Async`. The diagnostic sits on the method name, and its message names the return type.

### Failing Example

```csharp
public Task Place() => Task.CompletedTask;
```

### Passing Example

```csharp
public Task PlaceAsync(CancellationToken cancellationToken) => Task.CompletedTask;
```

### How to Fix

End the method name in `Async`.

## Notes

### What the Rule Ignores

An override, an explicit interface implementation, or an implementation of a member from an outside interface such as a framework contract never reports. The static `Main` entry point, the top-level statements entry point, and lambdas are out of scope. The rule does not run outside the production layers.
