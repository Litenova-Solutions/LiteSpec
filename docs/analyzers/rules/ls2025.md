# LS2025: Adapter Names a Type Outside Its Layer

LS2025 reports an adapter file in `Infrastructure/{Port}/` that names a Domain type outside typed identifiers, shared values and the types its ports name, or a WebApi type. The adapter implements the module's port from platform and library types; domain rules and HTTP stay out of it.

## Reference

### What the Rule Enforces

LS2025 enforces [Follow Layer Direction in Every File](../../backend/dotnet/architecture.md#follow-layer-direction-in-every-file) (`litespec/backend/dotnet/architecture#follow-layer-direction-in-every-file`). It runs on Infrastructure files inside a port adapter folder. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A name in an `Infrastructure/{Port}/` file reports when it resolves to a Domain type other than a typed identifier, a shared-kernel value or a type the interfaces of the ports the adapter implements name in their member signatures, or to a WebApi type. A typed identifier is a type whose name ends in `Id`, and a shared-kernel value is a type in the Kernel project or outside every module. A port-named type is a type an implemented port interface names in a parameter, a return or a type argument, or one level deeper in the member signatures of such a type. The diagnostic sits on the name, and its message names the type and why the layer may not name it.

### Failing Example

```csharp
namespace Claimwick.Export.Ports.WorkspaceArchive;

internal interface IWorkspaceArchive
{
    void Write(WorkspaceArchiveInput input);
}
```

with the adapter:

```csharp
namespace Claimwick.Export.Infrastructure.WorkspaceArchive;

internal sealed class WorkspaceArchiveWriter : IWorkspaceArchive
{
    public void Write(WorkspaceArchiveInput input)
    {
    }

    public void Rebuild(Expense expense)
    {
    }
}
```

with the files in `Export/Ports/WorkspaceArchive/` and `Export/Infrastructure/WorkspaceArchive/`, and `Expense` the aggregate root. The port names only the gathered input, so `Rebuild` naming the aggregate reports.

### Passing Example

```csharp
namespace Claimwick.Export.Ports.WorkspaceArchive;

internal interface IWorkspaceArchive
{
    void Archive(Expense expense);
}
```

with the adapter:

```csharp
namespace Claimwick.Export.Infrastructure.WorkspaceArchive;

internal sealed class WorkspaceArchiveWriter : IWorkspaceArchive
{
    public void Archive(Expense expense)
    {
    }
}
```

The port names the aggregate in its signature, so the adapter implementing that signature names it without a finding.

### How to Fix

Pass the adapter only the input it needs: the handler gathers plain data and hands it to the module's port, and the adapter works from that input with platform and library types. When the adapter must work with a Domain type, name that type in the port interface signature instead: the adapter may name every type its ports name.

## Notes

### What the Rule Ignores

A file outside every port adapter folder never reports: `Persistence/` holds the repositories, which name their aggregates by design. A Domain type the interfaces of the ports the adapter implements name in their member signatures never reports, one level into the types they name. A name that resolves to no project source file never reports. References between two use cases' folders stay with LS2019.
