# LS5012: Permission Grants an Undeclared Role

LS5012 reports a permission that grants a role no record declares. Each permission record lists in `grantedTo` the roles it grants, and every entry must be a role the role records define; a permission granting anything else grants to something nobody defined.

## Reference

### What the Rule Enforces

LS5012 enforces [Generate the Registry, Permissions, and Roles from the Records](../../backend/dotnet/stack.md#generate-the-registry-permissions-and-roles-from-the-records) (`litespec/backend/dotnet/stack#generate-the-registry-permissions-and-roles-from-the-records`). It runs on Domain, Application, Infrastructure, and WebApi files, where the generator writes permission entries. Its category is `LiteSpec.Traceability`.

### What the Rule Reports

The generator reads each permission's `grantedTo` list against the role records, so that every granted role is one the role list defines. A permission granting a role no record declares is still emitted, and the rule reports it, naming the permission and the role. The diagnostic has no source location, because the unknown role lives in the records.

### Failing Example

The `permission/mint-money` record grants `role/ghost`, which no role record declares, so the entry carries it and the rule reports.

### Passing Example

The `permission/post-reimbursement` record grants `role/finance`, which the role list declares, so the entry carries it and the rule stays silent.

### How to Fix

Add the role to the role records, or remove it from the permission's `grantedTo` list, so every granted role is one the list defines.

## Notes

### What the Rule Ignores

The rule does not run in test projects, where no permission entries are generated.

It stays silent when no `.litespec/project.yaml` is in reach, or when the docs root it names cannot be resolved; the CLI owns that configuration error.

### Severity

The rule is an error whenever it fires, because the permission grants a role the role list does not define. An `.editorconfig` entry for the rule id overrides it.
