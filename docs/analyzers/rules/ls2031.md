# LS2031: Event Name Lacks Its Kind Suffix

LS2031 reports an event type whose name does not end with the suffix of its kind. A codebase holds three kinds of event: the domain event an aggregate raises for its own module, the module event other modules consume, and the integration event that leaves the product. A bare name never says which contract the type carries, so each kind ends in its own suffix.

## Reference

### What the Rule Enforces

LS2031 enforces [Name Every Event Type by Its Kind](../../backend/dotnet/naming.md#name-every-event-type-by-its-kind) (`litespec/backend/dotnet/naming#name-every-event-type-by-its-kind`). It runs in Domain and on Contracts projects. Its category is `LiteSpec.Layers`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

A type implementing an interface named `IDomainEvent` in Domain reports unless its name ends in `DomainEvent`. A type in a Contracts project carrying a mark that names a `module-event/` record reports unless its name ends in `ModuleEvent`, and one carrying a mark that names an `integration-event/` record reports unless its name ends in `IntegrationEvent`. The diagnostic sits on the type name, and its message names the kind and the required suffix.

### Failing Example

```csharp
public sealed record OrderPlacedEvent(int OrderId) : IDomainEvent;
```

with the file in `Orders/Domain/Orders/`. The type is a domain event, so it ends in `DomainEvent`.

```csharp
/// <implements>module-event/orders.order-placed</implements>
public sealed record OrderPlaced(int OrderId);
```

with the file in the orders module `Contracts/Orders/` folder. The mark names a module event, so the type ends in `ModuleEvent`.

### Passing Example

```csharp
public sealed record OrderPlacedDomainEvent(int OrderId) : IDomainEvent;
```

with the file in `Orders/Domain/Orders/`.

```csharp
/// <implements>module-event/orders.order-placed</implements>
public sealed record OrderPlacedModuleEvent(int OrderId);
```

with the file in the orders module `Contracts/Orders/` folder.

### How to Fix

End the type name in the suffix of its kind: `DomainEvent` for a domain event in Domain, `ModuleEvent` for a fact in Contracts whose mark names a `module-event/` record, and `IntegrationEvent` for one whose mark names an `integration-event/` record. Keep the fact stem the mark names: a handler answers the fact without the suffix, as `NotifySubscribersOnOrderPlacedHandler` answers `OrderPlacedDomainEvent`.

## Notes

### What the Rule Ignores

Interfaces never report. A Contracts type with no event mark never reports, whatever its name, because the mark states the kind. A type implementing `IDomainEvent` outside Domain and outside Contracts never reports. The rule does not run in a Test file.
