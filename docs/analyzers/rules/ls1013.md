# LS1013: Switch Leaves a Sealed Case to Its Discard Arm

LS1013 reports a switch in Domain that leaves a sealed case to its discard arm. A switch over a state or closed-set record hierarchy should name every case, but the C# compiler does not check that it does. A sealed case with no arm of its own silently reaches the discard arm at run time.

## Reference

### What the Rule Enforces

LS1013 enforces [Model every Aggregate lifecycle with state records](../../packs/dotnet/domain.md#model-every-aggregate-lifecycle-with-state-records) (`litespec/packs/dotnet/domain#model-every-aggregate-lifecycle-with-state-records`) and [Model every closed set of domain values without enums](../../packs/dotnet/domain.md#model-every-closed-set-of-domain-values-without-enums) (`litespec/packs/dotnet/domain#model-every-closed-set-of-domain-values-without-enums`). It runs in Domain only. Its category is `LiteSpec.Domain`. Severity and enablement follow the [Analyzers overview](../README.md).

### What the Rule Reports

The rule reports a switch expression or switch statement whose input type is an abstract record with sealed cases in the compilation. It reports when the switch has a discard arm or a default label and no unguarded arm covers a sealed case or an abstract intermediate that covers it.

An arm with a `when` guard does not cover its case, because the guard can fail and pass the value to the discard arm. An arm covers its case with a designation, such as `OrderDraftState draft`, or with the type alone, such as `OrderDraftState`. An `or` pattern covers every case its operands name.

The rule reports one finding per switch, naming only the sealed cases with no arm of their own. A discard arm after every sealed case reports nothing: it satisfies the compiler, which cannot prove a record hierarchy closed. The diagnostic sits on the discard pattern of a switch expression, or on the default label of a switch statement.

### Failing Example

```csharp
public abstract record OrderState;

public sealed record OrderDraftState : OrderState;

public sealed record OrderPlacedState : OrderState;

public sealed record OrderCancelledState : OrderState;

public sealed class OrderRouter
{
    public string Describe(OrderState state) => state switch
    {
        OrderDraftState draft => "draft",
        OrderPlacedState placed => "placed",
        _ => "other",
    };
}
```

### Passing Example

```csharp
public abstract record OrderState;

public sealed record OrderDraftState : OrderState;

public sealed record OrderPlacedState : OrderState;

public sealed record OrderCancelledState : OrderState;

public sealed class OrderRouter
{
    public string Describe(OrderState state) => state switch
    {
        OrderDraftState draft => "draft",
        OrderPlacedState placed => "placed",
        OrderCancelledState cancelled => "cancelled",
        _ => "other",
    };
}
```

### How to Fix

Add an unguarded arm for every sealed case, keeping the discard arm or default label for a value outside the sealed set.

## Notes

### What the Rule Ignores

A switch with no discard arm or default label never reports: the compiler warning CS8509 covers that switch. The rule also ignores a switch over a type that is not an abstract record, a hierarchy holding an unsealed case, and a hierarchy whose sealed cases sit outside the compilation. The rule does not run outside Domain.
