# Lower Layers Practice

The lower areas of LiteSpec are Behavior, Implementation, Proof, and Governance. They sit below the Intent records. This research record holds the findings of an outside review of those 4 areas, made on 31 October 2026. The reviewers read each area as a newcomer would, compared it with outside practice, and checked each finding in the files. It matters because several findings concern checks that pass when they should fail, or that claim more than they check.

## Findings

The review confirms that exceptions are uneven and too wide [model page][model] [release page][release]. It confirms that proof words overclaim, that tooling fails open, and that some design departs from outside practice without a stated reason [model page][model] [release page][release] [manifest][litespec-manifest] [Behavior page][behavior].

The review uses 4 reviewers, and each reads one area against branch v3 at commit `c9b2725` [Behavior page][behavior] [model page][model] [release page][release] [access page][access]. The Governance reviewer confirms behavior on scratch builds, and the reviewers recheck 5 code claims in the code on the same day [Behavior page][behavior] [model page][model] [release page][release] [access page][access]. The review never repeats the 124 findings that the findings table already verifies [Behavior page][behavior] [model page][model] [release page][release] [access page][access].

Exceptions are uneven and too wide [model page][model] [release page][release]. A known gap suppresses a tier G finding on presence alone [model page][model] [release page][release]. A deviation asks for a recorded reviewer, but a deviation holds every finding on its subject, not only the findings its provision governs [model page][model] [record schema][record-schema] [release page][release]. So a deviation that cites a precedence provision suppresses unrelated findings [model page][model] [release page][release]. Deferrals and the frozen phase relax blocking checks with no reason and no expiry [model page][model] [release page][release]. That conflicts with the scope rule that each waiver resolves to a deviation record [model page][model] [record schema][record-schema].

Expiry uses 4 field names, and a deviation expires without a report [model page][model] [record schema][record-schema]. A retired subject suppresses tier G findings [model page][model] [release page][release]. The review proposes one exception record to replace the deviation, the known gap, the deferred provisions, and the frozen check phases [model page][model] [record schema][record-schema] [release page][release]. The record holds the kind of waiver or gap, the provision or finding codes it covers, and the subject or paths [model page][model] [record schema][record-schema]. It also holds the reason, the exit, and `expiresOn` [model page][model] [record schema][record-schema]. It covers only what it names, and `exception-expired` reports it after its date [model page][model] [release page][release].

Agreement happens at merge [model page][model] [release page][release]. What is in git is decided, and a record present on the main line carries the team agreement [model page][model] [release page][release]. Outside practice favors separation of duties [OWASP LLM Top 10][owasp-projects-top-10-for-large-language-model]. The OWASP LLM Top 10 project asks for human approval of high-impact agent actions [OWASP LLM Top 10][owasp-projects-top-10-for-large-language-model]. LiteSpec serves one-person teams, so it keeps no second-reviewer rule [model page][model] [OWASP LLM Top 10][owasp-projects-top-10-for-large-language-model]. A team that needs separation of duties adds it above the merge [model page][model].

`Verified` never means what it says [model page][model] [release page][release]. The builder creates browser proof links with a null pass state, while every proof reader asks for a true pass state [model page][model]. So a scenario proved only by Playwright is never passing [model page][model] [release page][release]. A use case proved only by Playwright is never verified, and a step served only by browser flows is never exercised [model page][model] [release page][release]. Cucumber reports a status for each scenario instead [Gherkin reference][cucumber-docs-gherkin-reference].

A git-ignored cache holds the staleness state, and the cache is empty in every fresh clone [model page][model] [release page][release]. So CI never sees a changed scenario, and locally a rerun of an unchanged test clears the cache [model page][model] [release page][release]. Nothing blocks on an unverified scenario [model page][model] [release page][release].

An assertion-free test still marks records tested [model page][model] [release page][release]. Background use cases verify through any `when` and `then` step, and the docs never say so [model page][model] [Behavior page][behavior]. `verified` names 2 predicates, while `tested` and `exercised` overlap [model page][model]. The book recomputes proof state with its own vocabulary, across thousands of lines [model page][model].

The proposed repair keeps proof state in a committed proofs file [model page][model] [release page][release]. The file holds each scenario hash and its test body hash at the last passing run [model page][model]. A scenario is stale when either hash changes, and proof readers read browser outcomes [model page][model]. A finding blocks or reports by its tier [model page][model] [release page][release]. `use-case-unverified` reports by default [model page][model] [release page][release]. The release flag makes release-readiness items block, and the since flag blocks only on what changed [release page][release].

The proposed repair also keeps 4 proof words, each with one meaning [model page][model]. `verified` applies to a use case, `met` to a requirement, `tested` to a passing test with an assertion, and `exercised` to a flow step [model page][model]. Finding codes follow the subject and problem pattern, with 15 problem words [model page][model]. An unknown code fails the build, and the book renders the model file without judging anything itself [model page][model].

The review proposes 2 more repairs [Behavior page][behavior] [model page][model] [Gherkin reference][cucumber-docs-gherkin-reference]. Teams retire a refusal code and never rename it, and a scenario names the rules it shows in `exercises` [Behavior page][behavior] [record schema][record-schema]. The proposal lets a use case hold a shared background, as Gherkin allows [Behavior page][behavior] [Gherkin reference][cucumber-docs-gherkin-reference]. In Gherkin, `Rule` groups the scenarios of one business rule, and `Background` holds the `Given` steps shared before each scenario [Gherkin reference][cucumber-docs-gherkin-reference].

The tooling fails open in 4 places, and it matches marks by name [manifest][litespec-manifest] [Behavior page][behavior] [model page][model]. The manifest pins the analyzers to a release that lacks the traceability rules the stack pages cite [manifest][litespec-manifest]. The analyzer project carries the newer version [manifest][litespec-manifest]. A missing frontend reader turns S findings into reports, so the build passes despite the findings [model page][model] [manifest][litespec-manifest]. An unknown layer value disables every rule without a report, and a Worker project resolves to no layer at all [model page][model] [Behavior page][behavior].

The proposed repairs match each failure [manifest][litespec-manifest] [model page][model] [Behavior page][behavior]. The analyzer pin matches the analyzer project, with every cited LS code shipped [manifest][litespec-manifest]. The checker reports an unknown layer name, and Worker becomes a layer [model page][model] [Behavior page][behavior]. `Reader-missing` blocks when CI is set [model page][model].

Marks fail in 3 ways [Behavior page][behavior] [model page][model]. Marks take the declared style on frontends, a third syntax on operations files, and name matching on backends [Behavior page][behavior] [model page][model]. A handler in one folder that is marked for another folder passes [Behavior page][behavior] [model page][model]. The Blazor reader runs its own narrower regex, and no check reports a state change without an event [Behavior page][behavior] [model page][model]. The proposed repairs are that mark style belongs to the language and one parser reads it [Behavior page][behavior] [model page][model]. A backend mark matches its folder, and the checker recognizes marks and handlers by symbol [Behavior page][behavior] [model page][model]. A state-changing aggregate method needs a mark [Behavior page][behavior] [model page][model].

The architecture-test library stays dormant with its last release in 2021 [ArchUnitNET repository][github-tng-archunitnet]. The review proposes that the active ArchUnitNET line replace it [ArchUnitNET repository][github-tng-archunitnet].

Design departs from outside practice in the behavior records without saying why [Behavior page][behavior]. Atomic writes across aggregates contradict the page's own one-step-per-aggregate definition [Behavior page][behavior]. So an atomic write across aggregates stays allowed only through an atomicity rule that binds the group [Behavior page][behavior] [record schema][record-schema]. Coordination across aggregates belongs to the workflow-engine extension [Behavior page][behavior].

Other design waivers also have repairs [Behavior page][behavior] [record schema][record-schema]. Domain-event payloads and use-case inputs carry no type or schema, although the trust rule says the fields are fit to act on [Behavior page][behavior] [record schema][record-schema]. Following CloudEvents `dataschema`, inputs and payload fields carry `type` and `required` [CloudEvents spec][github-cloudevents-spec]. The repair lets an integration event name `dataschema`, and money values are `amount` with `currency` [CloudEvents spec][github-cloudevents-spec] [record schema][record-schema].

The retention schedule claims GDPR Article 30 order but omits purposes and other categories [GDPR Article 30][gdpr-info-art-30-gdpr] [Behavior page][behavior] [record schema][record-schema]. Article 30(1) asks for identity, purposes, data subjects and categories, recipients, transfers, time limits, and security measures [GDPR Article 30][gdpr-info-art-30-gdpr]. So each data class and retention row states its purpose, and each period is an ISO 8601 duration [GDPR Article 30][gdpr-info-art-30-gdpr] [record schema][record-schema]. The schedule claims only the time limits of a record of processing, and counsel confirms the wording [GDPR Article 30][gdpr-info-art-30-gdpr].

`Pseudonymize` sits as an erasure position [Behavior page][behavior] [record schema][record-schema]. Recital 26 says pseudonymized data stays personal data, and only anonymous information falls outside the principles [GDPR Recital 26][gdpr-info-recitals-no-26]. So `pseudonymize` keeps the class personal with its basis, and the repair adds `anonymize` [GDPR Recital 26][gdpr-info-recitals-no-26] [record schema][record-schema].

Entry points cover outside callers, triggers, and content, and 2 pages assign `auth` to them [access page][access] [Behavior page][behavior]. So an entry point leads from outside only, and it states caller authentication [access page][access] [record schema][record-schema]. The use case states its permitted actors [Behavior page][behavior] [access page][access] [record schema][record-schema]. Reactions answer events, while jobs run on schedules or by hand [Behavior page][behavior] [record schema][record-schema]. So the review keeps reaction and job as 2 record types [Behavior page][behavior] [record schema][record-schema]. A reaction names the events it answers in `triggeredBy`, with its skip condition in `skippedWhen` [Behavior page][behavior] [record schema][record-schema]. A job names its kind as scheduled, one-off, or manual, with its schedule, selection, lease, cursor, and guard [Behavior page][behavior] [record schema][record-schema].

Several words carry 2 or 3 meanings [Behavior page][behavior] [access page][access]. The verbs `issue` and `publish`, the word `operator`, and the words `system`, `anonymous`, and `door` each do so [Behavior page][behavior] [access page][access]. The review makes effect verbs into `runs`, `sends`, `emits`, and `calls` [Behavior page][behavior]. A manual job carries `kind: manual` [Behavior page][behavior] [record schema][record-schema]. A coordinator step that a person runs is `person`, and the auth kind `anonymous` becomes `none` [Behavior page][behavior] [access page][access].
