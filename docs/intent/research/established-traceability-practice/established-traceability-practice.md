# Established Traceability Practice

Traceability links each requirement to the items it came from and to the items that implement and test it. This research record reviews established practice in requirements management, safety standards, goal methods, and tracking tools. It records what that practice requires of the top of the chain, which is the reason a feature exists. It also records where that practice warns against requiring those links. LiteSpec must decide how strict its links above the requirements should be, and the largest consumer's measured gap is exactly there.

## Findings

Established practice requires every requirement to name an origin [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements] [ERNI article][betterask-the-need-for-requirements]. It warns that links alone do not give traceability [traceability matrix post][adammhoward-solavirtusinvicta-traceability] [backlog post][nkdagility-resources-blog-rethinking-product]. The links need named tolerances, a rule for when a check turns enforced, and reasons behind them [link type reference][learn-microsoft-en-us-azure-devops] [work item links post][blogs-sw-siemens-polarion-links-between-work] [engineering elements post][blogs-sw-siemens-polarion-interconnecting-your] [parent issues docs][linear-docs-parent-and-sub-issues] [traceability matrix post][adammhoward-solavirtusinvicta-traceability].

ISO/IEC/IEEE 29148:2018 is the standard the IEEE navigator names for requirements work [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements]. Its pages state the rule directly: each requirement links back to its origins in stakeholder need [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements], and forward to the design elements, test cases, and delivered components that implement and verify it [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements]. A change's downstream impact is then visible before it ships [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements]. For LiteSpec this means every element needs a parent above and a child below, or the gap stays visible [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements].

IREB CPRE uses the same shape [ERNI article][betterask-the-need-for-requirements]. Traceability traces a requirement back to its origins, forward to its implementation and tests, and to the requirements it depends on [ERNI article][betterask-the-need-for-requirements]. It claims impact analysis, avoidance of unnecessary requirements, coverage, and progress measurement [ERNI article][betterask-the-need-for-requirements].

LiteSpec matches that shape in its forward links, and it is stricter on quality-requirement scenarios [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements] [ERNI article][betterask-the-need-for-requirements]. Its origin link is the gap [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements] [ERNI article][betterask-the-need-for-requirements]. `basedOn` exists, but LiteSpec defines `feature` narrowly [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements] [ERNI article][betterask-the-need-for-requirements]. So an ordinary shipped-feature requirement has no named origin, and both sources call it orphaned [requirements management topic][technav-ieee-topic-requirements-management] [technical requirements topic][technav-ieee-topic-technical-requirements] [ERNI article][betterask-the-need-for-requirements].

The regulated regimes require the chain rather than advise it [DO-178C guidance][jamasoftware-requirements-management-guide] [functional safety page][vector-business-unit-code-testing-and]. DO-178C traces requirements to code and to tests [DO-178C guidance][jamasoftware-requirements-management-guide]. It requires a requirement to justify every line of code and every test, and it treats untraceable code as extraneous [DO-178C guidance][jamasoftware-requirements-management-guide]. It scales rigor through Design Assurance Levels A to E, and it treats a suspect link as a state of its own [DO-178C guidance][jamasoftware-requirements-management-guide]. A suspect link is a changed item whose neighbors have not been reviewed again [relationship status help][help-jamasoftware-ah-manage-content-coverage] [suspect links help][help-jamasoftware-ah-manage-content-coverage-2].

ISO 26262 and IEC 62304 require bidirectional traceability with the same discipline [functional safety page][vector-business-unit-code-testing-and] [bidirectional traceability guidance][jamasoftware-legacy-requirements-management]. A team analyzes the full impact before it accepts a change, then propagates the update to every traced artifact [functional safety page][vector-business-unit-code-testing-and] [bidirectional traceability guidance][jamasoftware-legacy-requirements-management].

LiteSpec implements the regulated shape below the requirement line [DO-178C guidance][jamasoftware-requirements-management-guide] [functional safety page][vector-business-unit-code-testing-and]. Its computed staleness matches suspect-link semantics, done automatically [relationship status help][help-jamasoftware-ah-manage-content-coverage] [suspect links help][help-jamasoftware-ah-manage-content-coverage-2]. The regimes require the top of the chain as well, and LiteSpec leaves it optional [DO-178C guidance][jamasoftware-requirements-management-guide] [functional safety page][vector-business-unit-code-testing-and]. The record states that 719 of 928 consumer requirements name no origin and fail a DO-178C audit [DO-178C guidance][jamasoftware-requirements-management-guide]. Implementation with no linked requirement stays out of a certified build [DO-178C guidance][jamasoftware-requirements-management-guide]. LiteSpec needs no Design Assurance Level grading [DO-178C guidance][jamasoftware-requirements-management-guide].

The tasks are real maintenance tasks on 2 third-party projects, with 71 subjects [experiment abstract][link-springer-article-s10664-014-9314-z].
