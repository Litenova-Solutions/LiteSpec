# Changelog

## v1.17.0

- Added seven provisions to `docs/frontend/ui.md`, which turn the controlled UI contract from a set of declarations into a pipeline a validator walks. `FRONTEND.UI.DESIGN.001` requires a root `DESIGN.md` carrying the brand, tokens, vocabulary, patterns, do list, refusals, motion, and voice, because an agent that has read no contract picks its own and the picks differ on the next page. `FRONTEND.UI.COMPOSITION.002` and `FRONTEND.UI.COMPOSITION.001` make a repeated page shape a catalog recipe with a schema-valid sidecar, and make a page region name one rather than invent a layout. `FRONTEND.UI.STATE.001` refuses a sidecar that declares a state no component any region names carries, which is the shape of a page that lists `saved` and announces nothing. `FRONTEND.UI.GATES.001` refuses an implementation that renders a `data-region` the sidecar does not name, which is the section an agent added after freezing its plan. `FRONTEND.UI.PLACEMENT.001` and `FRONTEND.UI.ACCEPTANCE.001` put the acceptance record and its files in an `evidence` directory beside the route, and refuse an identifier with no record or no file.
- Rewrote `FRONTEND.UI.PROTOCOL.001` and tightened `FRONTEND.UI.PAGE.001`. The protocol asked an agent to search, compose, and record, and every step of it was checked by the agent that performed it. It now names four gates whose output is artifacts: a sidecar a validator reads and acceptance files a browser runs. The page rule now covers every route in the application tree rather than a page somebody judged non-trivial, and `schemas/ui-page.schema.json` gains a required `layout` from a closed set of five shapes, a `hiddenWhen` on a region, and the `row-expanded` state.
- Extended `FRONTEND.UI.EVIDENCE.001` with the matrix its own requirement had been naming. The provision said an author names evidence from the matrix in that section, and the section held no matrix.
- Added `schemas/design-contract.schema.json`, `schemas/composition-recipe.schema.json`, and `schemas/acceptance-criteria.schema.json`, with the `design-contract.md`, `composition.md`, `composition-recipe.json`, and `acceptance-criteria.json` templates a consumer copies. `standards.project.json` gains `paths.uiCompositions` for the catalog root.
- Moved the local JSON Schema evaluator into `tools/schema.mjs`. `tools/validate-ui.mjs` needed it for three new schemas, and a second copy would have drifted from the first in the way `tools/prose.mjs` already exists to prevent. The keyword gate moves with it, so a schema carrying a keyword no branch implements still fails rather than passing unread.
- Replaced `BACKEND.ARCHITECTURE.WORKER.001` with `BACKEND.ARCHITECTURE.WORKER.002` and `BACKEND.ARCHITECTURE.WORKER.003`. The old rule restricted when a Worker project may exist and never said where durable dispatch, queue consumption, workflow advancement, and scheduled work run without one. A consumer could therefore host four background services inside WebApi, deviate from no rule it could name, and record no decision, which is what one consumer did. The first new provision requires the execution host to be declared whichever it is, and the second states the three conditions that make a separate process the answer: independent scaling, independent deployment, and isolation from request-path resource limits. The outbox, jobs, and report extensions now activate the declaration rather than the project.
- Rewrote the boundary half of `BACKEND.DOMAIN.CLOSEDSET.001`. The rule forbade enums in Domain and the prose after its example then described a transport enum, a persistence discriminator, and an Application mirror in three paragraphs that read as permission. A reader following the rule refused enums everywhere and a reader following the rationale accepted them at the boundary. The four layers now sit in one table with one permitted form each, the transport enum has one stated condition, and the conversion back to a record case before a Domain call is written down, because without it the boundary exception readmits the integer the rule removed.
- Added `BACKEND.DOMAIN.MONEY.002`, which refuses `double` and `float` for a monetary amount, a rate applied to one, and a quantity compared for exact equality. The prohibition was a sentence in the rationale of `BACKEND.DOMAIN.MONEY.001`, where it obliged nobody and no verification row reached it.
- Reconciled `BACKEND.DOMAIN.ID.001` with `BACKEND.DOMAIN.TIME.001`. Version 7 embeds a timestamp, so the identity factory reads a clock that the no-clock rule appeared to forbid. The carve-out is now stated with its reason, and the collision question RFC 9562 leaves open is answered: the Domain writes no handling for it and a duplicate key fails like any other write conflict.
- Permitted the nested state-case form in `BACKEND.DOMAIN.CONVENTION.003` and `WORKSPACE.NAMING.SUFFIX.001`, and restated `WORKSPACE.NAMING.AGGREGATE.001` against the qualified name. `OrderState.AwaitingPayment` already leads with its aggregate through its declaring type, and the flat rule read as requiring `OrderAwaitingPaymentState`, which repeats the anchor twice. Both forms are now named, and a project picks one.
- Replaced `BACKEND.APPLICATION.MEDIATOR.001` with `BACKEND.APPLICATION.MEDIATOR.002` and moved the package to `BACKEND.APPLICATION.CONVENTION.005`. The Standard named two LiteBus members, so a consumer changing mediator overrode a Standard to keep a property the Standard was not actually about. The obligation is that the write and read paths stay separately dispatched; the members that supply it are a replaceable default.
- Titled `docs/backend/persistence.md` "Persistence" and added a Concepts section dividing its provisions into provider-neutral and provider-specific groups. The page was titled "Marten Persistence" while the manifest pinned EF Core for its own extension, so a consumer on the extension could not tell which of the twelve provisions moved with the provider. `COMMIT.001`, `NAMING.001`, and `SCHEMA.001` now name what each provider does, and `SCHEMA.001` says what a reviewed step is instead of leaving the tool unnamed.
- Added `WORKSPACE.STRUCTURE.DOTNET.002`, which permits one workspace-root solution listing more than one deployable unit. A workspace with an API and a command-line tool had no single file an editor could open across both, and the existing rule read as forbidding one. The API solution stays at `apps/api/` and stays the file `paths.apiSolution` names. The same change marks `AppHost` and `ServiceDefaults` as conditional in the tree example, because they are local hosting projects rather than application layers and their absence needed no override.
- Added `QUALITY.SECURITY.AUTHZ.002`, which requires a protected collection query to apply its authorization scope as a database predicate before paging. `QUALITY.SECURITY.AUTHZ.001` states a check against a target, and a collection has no single target, so the sentence covering it lived in a rationale. Filtering a materialized result is the shape OWASP names as broken object level authorization, and a page assembled from an unrestricted read leaks the total count even when every row is dropped.
- Added `QUALITY.SECURITY.ABUSE.002`, which requires one shared limit store across replicas. A per-process counter multiplies the declared limit by the replica count, so the limit a specification states is not the limit the system applies, and the multiplier changes when the deployment scales. This was also a rationale sentence.
- Added `QUALITY.OPERATIONS.TRACE.001`, which names W3C Trace Context `traceparent` and one configured propagator. `QUALITY.OPERATIONS.OBSERVABILITY.001` required a trace identifier and left its format open, so two hosts could each satisfy it and correlate nothing across the boundary between them. `BACKEND.API.ERROR.001` now cites RFC 9457 rather than the obsoleted RFC 7807, and states that its `traceId` is that header's trace-id.
- Added `QUALITY.OPERATIONS.ALERTS.002`, `QUALITY.CI.RELEASE.002`, and `QUALITY.CI.PROTECTION.002`. A declared severity with no destination is a label. An artifact with no component inventory cannot be checked against an advisory without rebuilding the dependency graph of a commit somebody has to find first. A branch-protection bypass that nobody recorded is indistinguishable from a habit, and it is the only case where a commit on the default branch was not reviewed.
- Enumerated the nine WCAG 2.2 criteria under `FRONTEND.COMPONENTS.ACCESSIBILITY.001`, with the level each one carries. The rule listed five properties a component can satisfy alone, and the nine additions are properties of a flow or a page, so a project targeting AA had no statement of what it had taken on.
- Added `FRONTEND.DATA.OPTIMISTIC.002`, which requires a reconciled optimistic outcome to be announced through a live region. A rollback is a silent visual change, and a reader using a screen reader heard the optimistic value announced and nothing afterwards.
- Added `FRONTEND.DATA.CONVENTION.005`, which runs the pinned generator without `--immutable`. The pinned `openapi-fetch` release wraps an immutable array in a type carrying no array methods, so `.map` over a response collection stops compiling; the defect is open upstream and the generator flag is what reaches it.
- Stated in `FRONTEND.RENDERING.STATE.001` and `FRONTEND.COMPONENTS.STATE.001` why their state lists differ. One listed six and the other seven, which read as a contradiction rather than as a route having `not-found` and a control having `disabled` and `pending`. `schemas/ui-page.schema.json` is named as the complete set.
- Extended nine extensions with the value each rule left to the reader. `EXT.AUDIT.PROTECTION.002` names SHA-256 and canonical serialization, because two implementations that each chose their own cannot verify each other. `EXT.AUDIT.PROTECTION.005` asks for an external checkpoint, because a chain proves records are consistent with each other and not that the whole chain was never recomputed. `EXT.AUDIT.READ.002` audits a bulk read inside one boundary, which is the shape a copied dataset has. `EXT.CACHE.KEY.002` refuses personal data in a key, because a key space is a store nobody classified. `EXT.CACHE.INVALIDATE.003` records a manual clear and `EXT.CACHE.FAILURE.003` separates a miss from an error from a degraded response, because a fallback that works is invisible. `EXT.OUTBOX.STATE.001` requires sealed records rather than four labels, since three of the four states carry data the others do not. `EXT.CONCURRENCY.IDEMPOTENTKEY.005` adds the actor to the fingerprint, because two actors can present the same client key. `EXT.CONCURRENCY.IDEMPOTENTOUT.003` adds the caching headers, which are computed for the exchange rather than for the result. `EXT.TENANCY.STORAGE.001` resolves the tenant at session creation rather than per query. `EXT.TENANCY.OPERATION.002` and `EXT.LIFECYCLE.PURGE.004` record an all-tenant run and a legal-hold release, which are the two events no single tenant's own trail holds. `EXT.REPORT.CONTENT.003` refuses a formula-leading value on import, because escaping on the way out protects this export and not the next one. `EXT.JOBS.TIME.001` became a MUST with a named time zone, because a local schedule runs twice on one date each year. `EXT.LOCALE.FORMAT.001` names the `Intl` constructors, and `EXT.LOCALE.ROUTES.001` states the path segment as the baseline shape.
- Added `docs/reference/decision-records.md`, which states what a consumer decision record holds and which fields cite it. `overrides[].decision` pointed at a path the standards never described, and the two outside conventions this template extends were named nowhere. It also states the rule an override has to satisfy: an override whose decision body justifies less than the provision it names is the same defect as an unnamed decision.
- Added an amendment procedure to `CONTRIBUTING.md`. An active provision ID identifies its current assertion, and nothing said what to do with the retired number, the citations, the summary bullet, the verification row, or the fixture case.
- Annotated every `schemaVersion` pin with why it is a constant. A schema evolution model that accepts a higher minor is a compatibility guarantee between releases, which `CORE.AUTHORING.SNAPSHOT.004` refuses. Each release pins one exact shape and a consumer absorbs every difference when it adopts, so the constant is the model rather than an omission. The annotation is there so the question is answered where it is asked.
- Closed the gaps in the local JSON Schema evaluator rather than adding a library. `tools/` ships dependency-free Node with no install step, and the keyword gate is what makes a local evaluator safe: a keyword with no implementation fails the schema instead of passing unread. The gate now reaches every position a subschema can occupy, where it previously stopped at four, and the evaluator implements the upper bounds, `anyOf`, `prefixItems`, `contains`, `propertyNames`, `patternProperties`, and `dependentRequired` that a schema author had no way to express. A `oneOf` failure now carries the first reason from each branch that rejected, instead of a count.
- Replaced `fs.globSync` in `tools/validate-consumer.mjs` with a walker built on `fs.readdirSync`. The call arrived in Node 22 and is still experimental, so it put a runtime floor on every consumer without the repository stating one. The walker also skips build output, which is why the reported surface count fell: a generated `AssemblyInfo.cs` carried no vocabulary and its presence depended on whether somebody had built the project.
- Fixed three parsing defects in `tools/validate-ui.mjs`. A class string ending at an escaped quote shifted every later token in the file into the wrong parse. A CSS brace or comma inside a quoted attribute value was counted as structure, so `[data-token=",.promo"]` reported a feature style that was not there. The Tailwind variant list now composes, so `group-data-[state=open]` is a variant rather than an arbitrary selector. The source lock's fingerprint is also checked against the preset fields recorded beside it, not only against the consumer configuration.
- Added a page registry pass to `tools/validate-ui.mjs`. A page naming a frontend nobody declared was selected by no per-frontend pass and reported nothing, and two pages sharing a route were each valid alone.
- Tightened the parity depth test from three path segments to four. A handler sitting directly in an aggregate folder passed and derived its identifier from the aggregate name, which no specification can carry.
- Gave every command `--help` and every validator `--format=json`. A caller reading the result had to parse the human lines back apart, which breaks the first time a message is reworded. `tools/validate-consumer.mjs` also lifts each controlled-UI problem into its own list, because a structured caller has no output "above" to look at.
- Added exit-code assertions to the consumer case suite and resolved the thirteen templates whose placeholders the fixture never filled. The suite had been validating those templates against literal `__TERM__` strings, which satisfy every rule that asks for a non-empty value.
- Added a Node matrix, a nightly run, step timeouts, the parity case suite, and a pull-request body check to the workflow. The parity suite had been in no gate, and the "Skipped Checks" section the template asks for was never read.
- Exempted a rejection table's reason column from the vocabulary scan and the cell measure, and added the mannered column to the same exemption. A column that lists refused words was already exempt, and the column beside it that explains the refusal was not, so a glossary generated from its own language record reported its own reasons as breaches. The exemption applies only inside a table that already carries a rejection column, so an ordinary reason column elsewhere stays measured.
- Moved the manifest pins to the versions the release runs. Central package management enforces what the manifest pins, so drift between the two makes the rule point at a version nobody resolves. `WORKSPACE.DEPENDENCIES.PINS.001` now says what it always meant: the manifest pins the baseline stack, and a consumer's own product packages are pinned in the consumer's central file under a decision record, because the manifest belongs to the release rather than to the consumer.

## v1.16.0

- Added the `tutorial`, `how-to`, `reference`, and `command` page classes, and split the guide class into the first two of them. One class was carrying four jobs. Its contract, `Purpose, optional Prerequisites, Procedure, Verification`, was asked to hold a first lesson, a recipe for a known task, a list of settings, and a command reference, and each of those is read by a different person for a different reason. A tutorial ends in `What you built` rather than `Verification`, because verification asks whether a procedure worked and a tutorial asks what the reader now has. The how-to contract is the former guide contract under its own name, so `docs/guide/` needed no page moved.
- Mapped `docs/reference/` and `docs/tools/` to a page class, and widened the stem pattern that decides a class to accept a hyphen. The pattern had required a single lowercase word, which every descriptive file name fails, so `pageClass()` returned null for all three guide pages and for `audit-obligations.md`. The guide contract had therefore been enforced on no page in the tree since the class existed, and the four pages it was written for were the four it never read. Turning the reference directory on failed `audit-obligations.md` at once, and that page is now written to `Intent, Reference, optional Notes`.
- Added `CORE.AUTHORING.DISCLOSURE.001`, `CORE.AUTHORING.DISCLOSURE.002`, and `CORE.AUTHORING.DISCLOSURE.003`, which place a page at one layer and require every command page to name what it runs. A procedure that lists what a command already does becomes a second copy of that command, and the copy is the part that drifts. `Underneath` is a required section rather than an optional one, so a command page that hides its mechanism fails rather than passing in silence, and a command with nothing separately runnable writes `None.` under the existing empty-section rule. That makes the third provision static at no cost, where an optional section would have left it to review.
- Added `CORE.AUTHORING.CONFIG.001` and the `configuration` kind behind it. A setting introduced inside whichever procedure needed it first is findable only by the reader who already knows which procedure that was. A configuration page carries the default, the scope, and what overrides each setting, and states its precedence order once rather than per setting.
- Added `CORE.AUTHORING.INDEX.002` and `INDEX_MISSING_ROUTING`, which require the documentation root to name each page class before its first navigation group. A reader who cannot tell a tutorial from a reference opens both and trusts neither. The check confirms the block is present and positioned; whether a reader can act on it stays a review question, because no validator reads for comprehension.
- Added the `tutorial`, `how-to`, `reference`, `command`, and `configuration` consumer kinds, in `schemas/specification-metadata.schema.json` and in the `KINDS` map that holds the same rules a second time by design. A repository that ships a command had nowhere inside its documentation root to document it, so the command reference lived beside the code, outside the tree the validator reads, unchecked for vocabulary, prose, and link resolution. Each kind declares the H2 order its class answers at, which is the first time the consumer validator checks a section rather than a metadata field. A consumer tutorial had no kind that fit, and the nearest one, `section-index`, states that a page is a directory index. That is the misclassification `CORE.AUTHORING.METADATA.004` exists to refuse.
- Added `templates/standard/tutorial.md`, `templates/standard/command.md`, and the consumer templates for the three new kinds, and renamed `templates/standard/guide.md` to `how-to.md`. Added `docs/tools/`, which documents the five commands this repository ships as command pages. `tools/README.md` now links to them rather than restating them, which is the rule this release asks a consumer to follow.
- Added `CORE.SYSTEM.SCENARIO.001`, `CORE.SYSTEM.SCENARIO.002`, `CORE.SYSTEM.SCENARIO.003`, and the `scenario-cast` specification kind, which together require every module, aggregate, use-case, domain-policy, and end-to-end-flow specification to state one concrete occasion for its subject. Every section a specification already carried states a rule, a state, or a mapping, and none of them says when the behavior happens or who is under pressure while it does. In one consumer of 377 behavior specifications, not one page said what was going on in the world when its operation ran: a shortfall resolution was triggered by "somebody works through the open shortfalls", which names the mechanism and leaves the reader unable to tell that a buyer had paid for a ticket that did not exist. A reader who cannot place an operation reads each of its rules as an arbitrary constraint. The cast is one record rather than a habit, because independent scenarios invent an organization and a buyer per page and nothing then carries between two pages read in sequence.
- Bounded a `Scenario` section to 120 words in `CORE.SYSTEM.CONVENTION.007`, replaceable through `scenarioWordLimit` in `standards.project.json`, and refused a rule, acceptance, or end-to-end identifier inside one. Both bounds exist to keep the section from becoming a second specification: prose that grows past a paragraph becomes the page a reader reads instead of the tables, and an identifier inside a scenario reads as a second definition of the rule it names. The illustration has no authority, so a scenario that contradicts the page it sits on is the part that is wrong.
- Added a `Scenario` section to the module, aggregate, use-case, domain-policy, and end-to-end-flow templates, a `scenario-cast.md` template for the reference record, and a `Write the occasion before the rules` step to the domain modeling guide. Each template states what its own kind's scenario shows, because the occasion behind an aggregate is one instance moving through its states and the occasion behind a use case is one moment.
- Gave the consumer validator's case suite a third expectation form, `{ absent }`, for a diagnostic that must not appear. A case that narrows one setting can make an unrelated rule fire, and `no problems at all` then asserts the wrong thing: narrowing the documentation root put the reference cast outside the scan, which failed a case about an unscanned page.
- Split the contracts every layer names out of Application into a fifth baseline project, `Application.Abstractions`, and amended `BACKEND.ARCHITECTURE.PROJECTS.001` to require it. Four projects left the cross-cutting contracts with nowhere to go but a folder inside Application, and a folder cannot decline what a developer puts in it. In one consumer that folder had reached 181 files and a tenth of the layer, with 23 children of which 8 carried the name of a sibling module, 99 files belonging to exactly one aggregate or module, and one file importing a use-case namespace. The project references Domain alone, so the compiler now refuses what review had been asked to catch: nothing in it can name a use case, a handler, or a module.
- Added `BACKEND.ARCHITECTURE.PLACEMENT.001`, which places a type at the lowest folder holding every consumer that names it. Placement had been a judgement call resolved by the word "shared", which is a claim about the future rather than a fact about the code, so it was never wrong at the moment it was made and always wrong later. Counting consumers is mechanical, and it derives the contracts project as the residue of the count rather than as a destination. Domain's shared kernel stays, because `BACKEND.ARCHITECTURE.CONTRACTS.001` closes its membership.
- Added `BACKEND.APPLICATION.PORT.002`, which declares a port where its consumers meet rather than in a project-wide folder of ports. `BACKEND.APPLICATION.STRUCTURE.001` already rejects grouping by technical type one level down, and a folder of every port in the system is the same mistake with a different noun. A port beside its aggregate is reviewed with that aggregate's specification; a port in a central folder is reviewed by nobody, which is how a consumer accumulated 54 single-module ports outside the module tree.
- Stated in `BACKEND.APPLICATION.CONVENTION.001` that only a use case gets a folder, and that anything else sits flat in the folder that owns it. Four different shapes for module-local code had grown in one consumer, including a `Shared` folder inside a module, and a folder named for a service reads exactly like a folder named for a use case until you open it.
- Replaced the `Shared` children in the Application layout example with the placement rule, and added `Pipeline/` for the pipeline's own stages. The example had said "only for types used by multiple modules" in a closing sentence and shown a folder of technical kinds above it, and the picture is what gets copied.
- Made the consumer validator fail closed on an unclassified file, and added `CORE.AUTHORING.METADATA.004` to state the rule. A Markdown file with no metadata block was skipped in silence and the run still reported PASS, so an unvalidated specification was indistinguishable from a sound one. A real consumer's domain policy index sat unchecked indefinitely while every page around it was validated. The file already carried the principle in a comment, and applied it only to a metadata object in the wrong wrapper. The error now names the file and the two ways out, because a directory index that owns no aggregate, use case, or policy declares `section-index` rather than an exemption. `paths.unstructuredDocs` declares the paths whose Markdown is navigation or prose, and each entry must be a repository-relative path that exists, so an exemption cannot be a typo.
- Resolved the documentation root from `paths.docs` and failed a scan that walks no Markdown. The root was hard-coded to `docs` while `paths.domainDocs` was configurable, so a consumer whose specifications live anywhere else scanned zero files and passed. That is the same fail-open shape as an unclassified file, one level up, and shipping the leaf without the root would have left the larger hole open. The report names the root it walked, so a thin scan is visible on a passing run rather than only on a failing one. The root is an explicit field rather than the common ancestor of `domainDocs` and `uiDocs`, because that ancestor is the repository root whenever the two live in separate trees, which widens the scan instead of narrowing it.
- Required every configured path to resolve. `domainDocs`, `uiDocs`, `apiSolution`, and each frontend path were accepted unread, so a typo disabled the use-case, workflow, and policy cross-file checks without a word. Each message now names the field, the value, and the checks the missing path silently switched off.
- Named the allowed values in every closed-set error, and described the expected form in every pattern error. `bad risk 'consistency'` stated what was wrong and never what was right, and the vocabulary existed only inside the validator, so three authors working from the templates independently invented `abuse`, `consistency`, and `privacy`. Each message now carries `expected one of ...`, matching the shape `platform` already used, and the kind list derives from the kind table rather than repeating it. A pattern error describes the form in words with an example, rather than printing a regular expression or the bare phrase `fails pattern`.
- Added `prohibitedKinds` so a consumer can declare a specification kind it does not use. A project whose agent instructions prohibited workflow specifications outright had no way to enforce that: the kind stayed valid, the template stayed on disk, and an agent reaching for it received a PASS while breaking the project's most explicit rule. The declaration makes the prohibition a contract rather than advice, and each entry must name a kind the validator knows, so a typo prohibits nothing visibly rather than silently.
- Added `CORE.SYSTEM.COVERAGE.001` and `tools/validate-parity.mjs`, which compares Application operation folders with use-case specifications in both directions. Nothing had ever compared the documentation with the code, and both directions hid real work: in one consumer fifteen aggregate roots carried a repository, persistence registration, and dependency wiring while no use case reached any of them, and eighty-one operations had no specification. Code with no specification reads as a reviewed feature and is not one. A `planned` specification with no handler is correct and is not reported. `--report` prints the same findings and exits zero, for a consumer burning down a backlog, and the failing behavior is the default. `parity` in the project file names the Application project when convention cannot resolve it, and carries the two ignore lists.
- Added `CORE.AUTHORING.DERIVED.001`, which requires a specification to name the source or the command behind a count, a census, or a membership list rather than restating it. Three hand-maintained registries in one consumer had drifted from the code they described, and one of them said so in its own text while staying wrong. A restated fact is accurate until the next unrelated commit, nothing reports the moment it stops being accurate, and a reader trusts a stale number exactly as much as a fresh one.
- Added `CORE.AUTHORING.PROSE.002` and `CORE.AUTHORING.PROSE.003`, which apply the controlled prose measures to a consumer specification tree and give the accepted debt an exit. The profile had existed since the repository did, and `tools/validate-standards.mjs` enforced it over these pages alone. A consumer inherited the rule and no check: one project of 459 pages carried 5694 measure violations while its validator reported a pass, because the run never looked at prose. A baseline records the count and the review date a page was accepted at, and `CORE.AUTHORING.PROSE.003` retires the entry when `lastReviewed` advances, so the debt burns down against the rereading a project already performs rather than through a separate campaign nobody schedules.
- Added `CORE.AUTHORING.TERM.002` and `CORE.AUTHORING.TERM.003`, and `schemas/language.schema.json` behind them. Terminology governance had been prose: a glossary column headed `Avoid` and a module table headed `Rejected synonyms`. Prose cannot be checked against prose, so both stated the rule to a reader and to nothing else. In one consumer the glossary defined `Seller` as the organizer and one module used the same word 21 times for the buyer facing that organizer, with both statements approved and neither reported. A rejection carries the scope it binds, because a word correct in one module is wrong in another, and the scope is a path expression rather than a module name so a policy page and a research note fall under it too.
- Added `CORE.AUTHORING.VOICE.002`, which refuses metaphor where a literal phrase carries the same meaning. A figure of speech defeats terminology review rather than merely reading poorly: a reader cannot tell whether it names a defined concept or decorates one, so it is never entered in a glossary and never rejected as a synonym. It also asserts more than its author chose. Three settlement routes described as rungs on a ladder claim an ordering the routes do not have, and the consumer that wrote it had no fourth route to place above or below them.
- Extracted the prose measures into `tools/prose.mjs`, which both validators now read. The measures had one implementation and one caller, so extending them to consumers would have produced a second copy, and a second copy of a rule is the drift the rule exists to prevent: each validator would keep reporting a pass against its own idea of the profile. `tools/validate-standards.mjs` produces byte-identical output across the change.
- Added `paths.language` and `prose.baseline` to `schemas/standards-project.schema.json`, and `templates/consumer/language.json` with its row in the template index. A language record that does not resolve names the checks its absence switches off, and a scope that is not a regular expression is an error rather than a rejection that silently matches nothing.
- Added `CORE.AUTHORING.TERM.004` and `paths.languageScan`, which take the vocabulary check to the surfaces a Markdown scan never reads. `CORE.AUTHORING.TERM.003` covers a consumer's specification tree alone, which is usually the smallest surface its words reach and the only one nobody drifts on. The consumer that motivated the rule has 459 pages, 4,390 source files, 3,458 interface strings, 1,005 API property names and 34 feature files, and every collision its own audit found lived outside the pages: one word naming five things, another naming the organizer in the glossary and the consumer in the shipped dashboard, in one dictionary file, in both languages. A pattern matching no file is an error rather than a quiet skip, because a surface switched off in silence reports the same pass as a surface that is clean.
- Added `checkLanguageInSource` to `tools/prose.mjs`, which scans a non-Markdown surface for the same two problems. It differs from the Markdown scan in three ways, and each one is a rule about what a word looks like outside prose. The fenced-block and rejection-column exemptions do not apply, because a source file is code throughout and has no column that exists to list refused words. Each line is read twice, once as written and once with identifier boundaries opened out, so `SellerOrderId` reports a rejection of `seller` while `load-bearing` survives the pass that would have split it; a hit found by both passes is reported once. A scope is matched against the repository-relative path for these files, because a file outside the documentation tree shares no other root with a page.

## v1.15.0

- Added the `audit` extension at `docs/ext/audit.md`. - Replaced the module-first Domain folder convention with a top-down `module` then `aggregate` then detail hierarchy, replicated in every layer (`ARCH.MODULES.001` and its mirrored-folders convention). A module with more than one aggregate gives each aggregate its own folder with its own `Events/`, `States/`, and `Exceptions/`, and a closed set groups its base and cases in a folder named for the concept (for example `ScanResults/`) while the aggregate state hierarchy keeps its `States/` folder. A single-aggregate module keeps its aggregate flat. Kind-bucket folders (`Entities/`, `ValueObjects/`, `Services/`) and empty folders remain prohibited. The Application, WebApi, and Infrastructure layer conventions show the same module-then-aggregate nesting.
- Added `NAME.AGGREGATE.001`, which anchors every aggregate-owned type on its aggregate root's full name in first position: events (`OrganizationMemberAccessChangedEvent`), state cases (`PostPublishedState`, aggregate-first), union bases and cases (`RefundOutcome`, `RefundSucceededOutcome`), aggregate value objects (`OrganizationLegalProfile`), child entities, and exceptions. The full aggregate name is used, never an abbreviation, and the prefix chains to the aggregate root. Only Shared kernel types (`Money`, `EmailAddress`) are unprefixed, signaled by their location. The anchor is the aggregate root, not the module (`ReservationNotFoundException`, not `InventoryReservationNotFoundException`), while failure codes stay module-scoped; child-entity identities follow `{Aggregate}{Part}Id`. Domain events now carry the `Event` suffix (`{Aggregate}{PastFact}Event`); an event-reaction handler and its folder keep the `On{PastFact}` form without the suffix. Updated `DOMAIN.STATE.001`, `DOMAIN.CLOSEDSET.001`, `DOMAIN.EVENT.001`, the Domain names table, `NAME.SUFFIX.001`, and the affected examples across the profile and guides.
- Tightened `DOMAIN.EVENT.001` so a domain event carries no `Exception`, `DomainException`, or other error object and is not named after the language error type. A failure that is itself the recorded fact is modeled as immutable domain data (a value object or discriminated-union case) and carried as event data.
- Extended `NAME.EXCEPTION.001` to reserve the `Exception` suffix for `{DomainType}{Reason}Exception` failure types and to prohibit `Exception` as a domain business term for an anomaly or manual-handling case (for example `CancellationExceptionRaisedEvent`), with domain-word alternatives. The exception name anchors on the aggregate root, so an `Event` finance-assurance rule is `EventFinanceAssuranceMislabeledException`.
- Refined `NAME.AGGREGATE.001` from migration experience: a child entity with a first-class domain name (`Reservation`, a child of `CapacityPool`) is itself the anchor for its own states and unions (`ReservationHeldState`, not `CapacityPoolReservationHeldState`); a union case whose concept already embeds the aggregate reorders rather than doubles it (`SuppressionLegalBasis`, `RoleEventScope`); and a per-aggregate folder is named with the plural of the aggregate root so it adds a proper namespace segment (`Claimwick.Domain.Audience.BuyerAccounts`) that does not collide with the singular aggregate type (which a singular folder would, tripping CA1724).
- Tightened `DOMAIN.REPOSITORY.001` so a required load uses `GetByIdAsync`, which returns the aggregate and throws the aggregate's own `{Aggregate}NotFoundException` (a `DomainException` owning its code, mapped to `404`) from the Infrastructure implementation. A command handler no longer repeats a null check or builds a not-found failure with a hard-coded code and message at the call site. A nullable `FindBy...Async` is reserved for a genuinely optional lookup.
- Bumped the manifest version to 1.8.0 and added the v1.8 consumer upgrade guide.
