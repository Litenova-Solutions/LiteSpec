# Changelog

Releases before v2.0.0 are in [the v1 changelog](changelog/v1.md).

## v2.0.0

This release describes every project as one typed model and replaces the v1 consumer contract. People and agents write intent records. The model builder reads the code, screens, tests, and test runs, and computes the links between the two. `docs/core/model.md` owns the record types, the links, the authority order, and the size and stack choices.

Every consumer is affected. A consumer on v1.18.0 adopts this release by accepting its complete contract and recording 2.0.0 in `reviewedStandardsVersion`. The entries marked **Breaking** name each v1 file, field, page, and check that no longer exists or no longer passes. The other entries add to the contract or raise pinned versions.

- **Breaking.** `standards.project.json` requires `size` and `stacks` in place of `profile`. Size is `small` or `large` and decides which record types and test projects apply. Stacks name `dotnet` for the backend and one of `react`, `svelte`, or `blazor-web` per frontend, and decide which technology pages and checks apply. The `dotnet-react`, `dotnet-svelte`, and `dotnet-blazor` profiles no longer exist.
- **Breaking.** `standards.project.json` no longer accepts `overrides`, `parity`, or `specSync`. A departure from a standard is an Exception record with its reason and review date. A finding a project accepts for now is a Known gap record with an owner and an end date: the model check reports the finding as known until that date, then fails.
- **Breaking.** A consumer page carries a record type from `docs/core/model.md` and validates against `schemas/record.schema.json`. `schemas/specification-metadata.schema.json` and the specification kinds no longer exist. Aggregate, domain policy, and end-to-end flow pages become the business record, rule, and journey record types. Workflow has no replacement.
- **Breaking.** Identifiers use the `type/home.name` form, chosen by a person and stable once approved. Numbered identifiers, the identifier maps, and `tools/identifiers.mjs` no longer exist.
- **Breaking.** `tools/validate-spec-sync.mjs` and `tools/validate-parity.mjs` no longer exist. The model builder computes which code implements a use case, which code calls it, and which test proves a case, and its `check` command reports what does not resolve.
- **Breaking.** Load plans and hand-written implementation status no longer exist. An agent queries the model for the records a task touches. A change adding no module, business record, frontend, dependency, or public boundary may skip the query and read the consumer agent context and neighboring code instead.
- **Breaking.** The React and Svelte frontend pages are merged into one stack-neutral page per concern under `docs/frontend/`, with short per-stack sections for what differs. Rules for one stack only are in `docs/react/components.md`, `docs/svelte/components.md`, and the `docs/blazor/` pages. The getting-started and domain-modelling guides are in `docs/tutorial/`.
- **Breaking.** Test projects run xUnit v3 on Microsoft.Testing.Platform. `standards.manifest.json` pins `xunit.v3`, `Reqnroll.xunit.v3`, and the Microsoft.Testing.Platform report and coverage extensions, and no longer pins `xunit`, `Reqnroll.xUnit`, or `coverlet.collector`. A consumer `global.json` sets the Microsoft.Testing.Platform test runner, because the .NET 10 `dotnet test` command refuses the VSTest mode for these projects. `docs/workspace/dependencies.md` shows the setting.
- **Breaking.** Root `global.json` sets `10.0.100` as its SDK version and rolls forward with `latestMajor`, so any .NET 10 or later SDK builds the workspace. A `global.json` pinning one SDK release with patch-only roll-forward fails `standards/rule/workspace-config.set-the-sdk-floor-at-the-workspace-root`, which replaces `standards/rule/workspace-config.pin-the-sdk-at-the-workspace-root`. The manifest names the .NET major release, `10`, in place of an SDK version.
- **Breaking.** Every Markdown link outside code on a record page points at an existing file by its relative path. An identifier is cited in backticks, never as a link target.
- Added `docs/core/model.md` with the record types, each answering one question. It states which types a small project keeps, which a large project adds, and which switch on per project. Every record carries an owner and a status of draft, approved, or retired. A draft names its decider and a decide-by date, and an approved record is replaced rather than edited. Only a decision carries `replaces`, and every decision names what it decides.
- Product, Constraint, Research, Decision, and Requirement state why the product exists and what it must do or guarantee. A Requirement is a promise, a behaviour, a quality, a target, or a practice. A target or practice is measured or kept outside the code, and a promise carries effective-dated values.
- Problem and Feature state who has a problem and what the product offers against it. A Feature is planned, shipped, later, or refused.
- Actor, Role, and Permission state who acts and what each may do. A role holds at a scope the project names in kebab case, such as `platform`, `tenant`, or `self`. Journey and Entry point state how each reaches the product.
- Module, Business record, Rule, Use case, Result, Case, and Event state how the business works. A Result is one success or one named refusal, and a Case is one working example.
- Limit and Runbook state the bounds the product runs within and how to run it. Standard, Exception, and Known gap state how the project builds, where it departs, and what it lacks. Term states what each word means in each language the product ships.
- Added the model builder at `tools/model/`, run as `dotnet run --project tools/model/Litenova.Model`. `build` writes `model.json` with the computed `implements`, `calls`, and `proves` links. `check` reports open findings and expired Known gaps and exits 1 on either. `render` writes the generated page regions, and `query` prints one record with its links both ways. A Known gap on a use case also covers the findings about its cases and results. [The model builder README](tools/model/README.md) states how it confirms a proof.
- Added `node tools/book/book.mjs`, which generates the project book from `model.json`. The book is a static site with one page per record, an index per record type, a lens per actor, a review page, a glossary, and search. [Book](docs/tools/book.md) describes its pages and review mode.
- Added `docs/core/product.md`. Business intent lives in the product brief and in product topic pages under `docs/product/`, grouped by area. A topic tells the situation, what the product does, the costs and risks, and the evidence. It states its requirements with identifiers that records cite, and describes no behaviour. Every product choice and refusal traces to a decision, and a topic's History is derived from the decisions that name it.
- Added the work order to `docs/core/product.md`: intent, then specification, then code. A draft decision is enough to build on before it is approved.
- Added the `delegation` extension in `docs/ext/delegation.md`. A delegating agent writes a brief before handing out work, restricts each worker to its paths, answers only unanswered questions, and verifies worker output before accepting it.
- Added the `stage` extension in `docs/ext/stage.md`. A consumer declares `pre-production` or `production`. A `pre-production` consumer names each provision it defers, with the date its deferral ends, in `deferredProvisions` on its `stage` selection. A recorded promotion decision ends the deferral.
- Made extension replacement machine-readable. `standards.manifest.json` records per extension the baseline provisions it replaces and the record types it switches on. A replaced baseline rule and its check do not apply beside the extension.
- Marked every standards provision `checkable` or `guidance` in its Verification row. A checkable row names the command that checks it, and a guidance row states the question a reviewer answers. `docs/reference/provisions.md` lists the mark for each provision.
- Added LightBDD as the second runner of the `bdd` extension, beside Reqnroll. A LightBDD scenario is a C# method on a feature class, and a `/// <proves>` tag on it names the case it proves. Its steps bind through the compiler rather than text matching. `standards.manifest.json` pins `LightBDD.XUnit3` 3.12.1 with `xunit.v3.mtp-v2` 3.2.2, because LightBDD 3.12 is built against xUnit v3 3.2.
- Changed `standards/rule/backend-testing.use-one-production-faithful-integration-harness`. The integration project starts the pinned PostgreSQL once per test run as an xUnit v3 assembly fixture, and isolates state with a `DatabaseReset` or a template database clone.
- Added personal-data provisions to `docs/quality/security.md`. A platform holding personal data keeps a per-store inventory, and erasure and export reach every store. No log carries personal data in clear, and an unsalted digest of personal data counts as personal data. A breach procedure meets its reporting deadline, and live data at rest is encrypted.
- Added operating provisions to `docs/quality/operations.md`. A project lists every sub-processor, every recurring job reports liveness, every alert names its runbook, and a restore is exercised before the first production data.
- Narrowed `standards/rule/backend-api.model-a-monetary-value-as-one-object` to response models and to requests where the caller chooses the currency. A request against a fixed-currency account carries the amount alone.
- Added `prose.enforcement` to `standards.project.json`. Set to `report`, the prose measures and the mannered terms print as advisories and do not fail the run. Rejected synonyms still fail.
- Exempted quotations from the prose measures. A blockquote that opens with a quotation mark holds a source's own words and is not measured. A blockquote in the page's own voice is still measured.
- Raised the .NET package pins: ASP.NET Core 10.0.13, Marten 9.50.1, Aspire 13.6.1, OpenTelemetry 1.19, Testcontainers 4.16.0, and LiteBus `7.0.0-preview.6`. `Microsoft.OpenApi` stays on 2.12.2, because `Microsoft.AspNetCore.OpenApi` 10.0.13 requires a 2.x version.
- Raised the npm pins: Node 24.22.0, pnpm 11.28.5, and Vite 8.3.4. `@lucide/svelte` replaces `lucide-svelte`, and the TanStack Svelte Query 6 examples pass an options accessor. TypeScript stays on 6.0.3, because `svelte-check` and `typescript-eslint` do not yet accept TypeScript 7.
- When the project file or the manifest is malformed, `tools/validate-consumer.mjs` printed a stack trace. It now prints the file path and the parse message. The tools also strip a leading byte-order mark before parsing Markdown or JSON.
- `tools/validate-standards.mjs` validates the shipped consumer `standards.project.json` template against its schema.
- The UI validator that `tools/validate-consumer.mjs` starts stops after 120 seconds, and a failure to start it prints its own message.
- This release takes effect as the `v2.0.0` tag, the immutable reference a consumer records in `reviewedStandardsVersion`.
